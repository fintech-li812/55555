上位依据：`交接给WorkBuddy与Web助手_当前全貌_20261027.md`。

## 1. 设计目标与红线

**目标**：一个 `.qwenwork.host` 网址就是全部。访客不装技能、不装 Python、不连本机 MCP，关掉开发者电脑仍然可用。

**四条不可让步的红线**：

1. **金额只有一个出处** —— 计算内核。浏览器、模型、数据库都不算钱，只搬运和展示。
2. **计算内核住在千问里** —— 不接受"千问出网址、别处算钱"的形态（这是 v3 被否的原因）。
3. **四个来源严禁混用** —— `source_id` 在服务端决定一切：读哪份输入、配哪个证据版本、能不能存。前端只显示结论。
4. **不写死、不美化** —— 页面上每个数字必须带 `run_id` 与 `source_revision`，能倒推到哪一个输入、哪一次计算；追不到的就标未验证。

## 2. 分层

| 层 | 位置 | 职责 |
|---|---|---|
| 展示层 | 浏览器 | 选来源、看检查清单、三类汇总、差异、报告、AI 对话框。**不参与金额** |
| 会话路由 | Node 服务端 | 访客会话、请求校验、来源路由、幂等 |
| 计算内核 | Node 服务端 | 移植自 `program_v1/src`，唯一的钱 |
| 守卫 | Node 服务端 | 身份/单位/勾稽/合成标识检查 |
| 来源注册表 | Node 服务端 | 四个来源的输入、证据、版本、可否保存 |
| AI 适配器 | Node 服务端 | 工具白名单，模型不得自填金额 |
| 存储 | 千问内置数据库（虚线，待探针） | 会话、计算、记录 |
| 黄金基准 | 本地 D 盘 Python（**在千问之外**） | 只做对拍裁判，不对访客服务 |

## 3. 数据流：一次计算到落库

```
1 选来源(source_id) → 2 读固化输入 → 3 内核算钱 → 4 守卫校验 → 5 预览带 run_id → 6 保存前重算 → 落库
```

- **第 2 步**：服务端按 `source_id` 取固化 fixture，校验 `source_revision` 与工作簿 SHA256。云端**不解析任何上传的 xlsx**。
- **第 3 步**：内部金额一律**整数分**。理由：原 Python 用 `Decimal`，JS `Number` 是浮点，照搬会出现非零尾差，导致本来为 0 的差异变成非零。只在渲染时转元。
- **第 5 步**：返回三类汇总、独立余额核对、差异、`can_save`、`run_id`。`can_save` 由服务端判定，不由前端按钮状态决定。
- **第 6 步（灵魂）**：**不信浏览器传回的任何金额**。服务端凭 `run_id` 取上次输入重算，与本次预览逐字段比对，完全一致才写；不一致即拒绝并保留原始错误，不静默改数。
- **幂等**：`owner + request_id` 唯一。结果不明时用原 `request_id` 回查，**不换号重复保存**。

## 4. 四个来源（严禁混用）

| source_id | 云端行为 | 可否保存 |
|---|---|---|
| synthetic_eight_sheet_v1 | 公开演示主来源 | 可（条件通过） |
| program_demo_v1 | 历史小样例 | 可（已在千问真实保存并回查） |
| program_difference_v1 | 负例 | **禁止保存**，必须展示 -1000 差异 |
| manufacturing_sample_v1 | 原埋错样例 | **blocked**，不得给出金额结果 |

公开版只暴露 synthesis/demo 两个来源；原埋错工作簿及其企业信息不上公网。

## 5. Node 化移植策略

**不是重写，是逐模块对移植 + 黄金值双跑对拍。**

移植顺序（按依赖自底向上）：

```
program_engine(123) → account_binding(207) → cash_selection(161)
→ source_audit(309) → eight_sheet_engine(176) → agent_guard(87)
```

合计约 1063 行核心逻辑需要移植（其余为 HTTP/MCP/配置外壳，由 Node 服务端天然替代）。

每一步的验收方式相同：**同一份输入，Python 与 Node 各跑一遍，逐字段比对**。

- 冻结契约：把现有 100 项测试的期望值抽成一份语言无关的输入/输出 JSON fixture。
- 冻结的黄金值：流入 185000.00 / 流出 108000.00 / 净额 77000.00 / 期末 177000.00 / 差异 0.00。
- 移植过程中 Python 代码**一行不改**，保持它作为裁判的可信度。
- **Stage 1 不依赖探针结果** —— 无论最终走 Node 化还是 WASM，这份契约与 fixture 都要用。

## 6. 验收标准（验收靠证据，不靠嘴）

| # | 验收项 | 通过条件 |
|---|---|---|
| 1 | 主来源正确性 | 页面上 185000/108000/77000/177000/差异0 全部来自 Node 计算，带 run_id 可复算；**不是前端写死的常量** |
| 2 | 负例 | program_difference_v1 算出 -1000 且保存按钮被服务端拒绝 |
| 3 | 阻断 | manufacturing_sample_v1 显示 blocked，页面上不出现任何金额 |
| 4 | 会话隔离 | 两个浏览器各自保存，互查不到对方记录 |
| 5 | 幂等 | 同一 request_id 重复提交不产生第二份记录 |
| 6 | 断后端 | 后端不可用时页面明确报错，**不显示上一次的成功结果** |
| 7 | 跨设备 | 开发者电脑关机，另一台设备仍能完整跑通第 1、4 项 |
| 8 | 对拍 | Python 基准与 Node 结果在全部 fixture 上逐字段一致 |

**不声称的事**：合成金额对平不等于真实企业准确率；100 项软件测试不等于风险模型验证；`full_data_gate_executed=false` 维持不变。

## 9. 明确不做的事

- 不做通用 Excel 导入器。
- 不做真实企业客户数据接入。
- 不对外开放 MySQL、不放宽旧 root/QA 隔离校验。
- 不做 RF / 评级 / 高级三态 / 多行业（原文属暂停或另期）。
- 不在浏览器放密钥。
- 不为了让某个演示更好看而放宽第 6 步重算校验。
