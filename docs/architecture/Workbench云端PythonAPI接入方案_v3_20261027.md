# Workbench 云端接入推荐方案 v3
日期：2026-10-27。用户要求设计：千问云端网页不能直接运行现有Python引擎，如何交付一个可公开访问的整体Workbench。
本轮为方案，不代表云端接口已部署、端口已开放或生产已发布。

## 推荐架构：千问动态前端 + Node接口层 + 阿里云Python API + MySQL
浏览器只访问一个*.qwenwork.host网址。千问Pages动态网站的Node服务端接同源/api请求，再通过HTTPS调用阿里云上的Python API。Python API调用现有计算与证据模块、生成结果和报告，MySQL仅由云端应用访问。
不在Pages内运行Python，不将算法重写为JavaScript，不让网页调用本机127.0.0.1或MCP stdio，也不要求访客安装技能。
Node只做网页会话、请求转发和响应处理；金融金额计算只有Python这一份。网页AI与按钮均调用同一组业务接口。

## 部署位置
- 千问Pages：现有前端升级为动态应用；同源/api接口、会话和服务端连接配置。默认域名用于用户访问。
- 优先复用现有阿里云ECS：独立部署Python Web API，重用eight_sheet_engine、账户绑定、现金选择及结果校验。先核查服务器当前资源和环境；旧2026-10-22记录不是今日资源证明。
- HTTPS入口：反向代理/网关对外提供443，转发到仅监听回环的Python服务；域名、证书和平台出口实际可达性需部署前核验。API地址是服务端配置，不让用户自己填任意URL。
- MySQL：保持回环/私网，新增演示应用的限定账号及独立存储范围。原隔离QA入口、root/socket连接、历史21条记录不直接公开，不复用为任意访客写库通道。
- 配置与密钥：仅在Node/Python服务端配置，不进HTML、浏览器JS或发布包。具体配置入口需在千问动态平台实测。

## 用户工作流
打开网址 → 选择完整合成样例 → 已列数据检查 → 程序实际计算 → 三类汇总及独立余额核对 → 导出 → 明确点击保存 → MySQL提交回执 → 精确回查/历史。
公开演示仅使用synthetic_eight_sheet_v1，保留SYNTHETIC；任何人可打开并体验合成计算。
服务端给每个访客建立独立演示会话；保存和回查限定该会话，不能查看或覆盖其他人的记录。真实企业和多人协作阶段再启用登录、组织、角色及企业隔离；未实现的真实上传/管理入口不显示可用。
访客没有真实业务数据权限，原制造业埋错工作簿及其企业信息不公开。

## Python API契约草案
- GET /v1/health：版本、依赖状态；不泄露凭据。
- GET /v1/sources：公开演示来源白名单。
- GET /v1/sources/{id}/audit：该来源的实际检查及未执行项。
- POST /v1/calculations：{source_id}；服务端返回calculation_id、本次result、来源/算法版本、can_save。
- POST /v1/records：{calculation_id,request_id}；服务端校验会话归属、按固定来源和版本重算，然后真正提交。无需信任浏览器自填金额。
- GET /v1/records/{id}及按request_id精确查询：始终验证所属会话/企业。
- GET /v1/reports/{id}?format=json|txt：取本次结果，不拼接其他来源；PDF/任意Excel导出另做真实实现。
- POST /v1/assistant/messages：模型与工具编排；禁止直接执行模型生成的SQL/系统命令。
接口均为待实现草案，不是已上线URL。

## 身份、存储与幂等
Node与Python之间有服务身份验证；访客上下文由服务端会话产生并签名传递，不能相信浏览器或模型自报tenant_id/user_id。浏览器仅持有安全会话cookie。
公开演示保存使用独立应用表/库，包含owner_session_id、source_revision、run_id、request_id、payload_sha256、记录及时间；owner+request唯一。使用限定应用账号、参数化SQL。
保存结果不确定时，用原request_id回查，不换号重复保存；committed回执只在真实提交后产生。旧QA存储/Config的root及fixture策略保持，不为上线放宽旧校验；公共会话仓储单独封装。

## AI工作流
网页AI助手从服务端调用已配置模型API，工具白名单为检查、计算、读取结果、报告、经用户确认的保存和回查。金额来自Python工具，不让模型心算替代。
千问聊天技能不会自动变成网页中的AI助手。模型API地址、模型名、服务端密钥或平台已验证的Agent桥接需要单独配置；缺少配置就明确未接通，不能假装AI可用。
保存由界面确认动作或用户明确指令触发，模型不能自行决定提交或访问其他会话。

## 实施顺序与验收
1. 先做Python API与公共演示会话仓储的本地可审版本，复用现有计算；补身份/隔离/幂等/错误测试。
2. 部署到现有ECS的独立应用目录与应用账号，配置HTTPS并从平台出口实测；不碰原正式库和既有服务。
3. 做千问Node同源接口层，前端接真实API，预览计算、异常、保存回查、报告。
4. 接网页AI服务与同一工具，验证选择来源、差异阻断、明确保存及精确回查。
5. 发布到实际千问域名，从另一台设备访问验收；关闭开发者电脑后仍能使用。记录版本、结果、日志和回退方式。
公开域名测试须证明总流入185000、总流出108000、净额77000、期末177000、差异0来自程序，不是写死数据。不同会话无法互查记录；后端断开时明确报错且不显示旧成功。
真实企业验证、原样例裁决、通用导入和高级风险模型不因公开演示发布而自动完成。

## 上线前需核实的条件

这里只列配置项，不要求在聊天中发送密码或密钥。无需为了本方案先购买第二台服务器，是否需扩容以实际资源检查为准。
