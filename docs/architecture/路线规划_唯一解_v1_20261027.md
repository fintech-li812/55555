# 路线规划 v1：红线约束下的唯一解

日期：2026-10-27 中午。依据：两轮探针实测（V1 `77c55620…` + V2 `8e129ed6…`）。
性质：**路线规划**，不是上线通知。所有结论来自实测事实，不来自愿望。

---

## 0. 推导

本节路线不是"挑一个最好的"，而是**把不可能的都划掉，剩下的就是答案**。

### 第 1 步：列出全部红线

| 类型 | 红线 |
|---|---|
| 官方 | 不得把 secrets 打进发布包（`.env` 被硬拦，改名混包属违规） |
| 官方 | 不得含符号链接 |
| 我方 | 金额只有一个出处，且必须住在千问里 |
| 我方 | 四个来源严禁混用，负例禁存，阻断来源不给结果 |
| 我方 | 不写死结果，不谎称保存成功，不做没有后端支撑的假 AI |
| 我方 | 不对外公开真实企业数据 |

### 第 2 步：用红线逐个消解岔路口

| 决策点 | 划掉的选项 | 为什么死 | **幸存** |

### 第 3 步：四选一相乘，只有一条路

> **计算搬进千问的 Node 里算 → 数据存在千问的内置库 → AI 第一版不做 → 导出端点必做**

这条路上**没有任何一个组件在千问之外**。它是唯一一条同时满足"可公开访问""完整功能""不碰任何红线"三条的路径。

## 1. 唯一路线（一句话版）

> 一个 `.qwenwork.host` 网址，页面 + 计算 + 存储 + 导出全在里面，对外只说"没有 AI"，等条件成熟再谈 AI。

## 3. 这条路对讲座答案的鲁棒性

这是本路线最重要的性质——**它不押注任何一个下午才会知道的答案**。

| 下午可能问到的答案 | 本路线是否需要改 |
|---|---|
| A1 官方有/无判定标准 | 都不影响，我们内生到底 |
| A2 外部代理算不算破线 | **算** → S6 永久不做 AI，路线不变；**不算** → S6 可接，路线仍不变 |
| A3 计算外置叫什么 | 无论叫什么，我们已经选了不外置 |
| B1 env 能否注入 | 已实测不能，我们本就没指望它 |
| D4 付费门槛 | **免费可挂** → 省钱，路线不变；**必须标准版** → 按预算走，路线不变 |
| **A4 该押网页还是押编排** | **若为"押编排"，本路线作废，必须重画** |

**唯一的单点风险是 A4。** 其余所有答案只影响成本与附件功能，不影响主干。

---

## 4. 唯一能推翻这条路的东西

只有一件：**如果千问办公认为"核心"应该押在任务/工作流/智能体编排上，而不是押在网页上。**

那就意味着我们这半天讨论的"网页 = 工作台"整个前提不成立，正确形态可能是：
网页只做一张脸，真正的计算与编排由千问的任务系统在云端跑。

这个答案如果成立，重画成本不小，但**早知道远好过晚知道**——所以它必须今天就问出来。
