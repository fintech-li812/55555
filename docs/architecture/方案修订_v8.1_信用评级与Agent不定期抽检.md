# 方案修订 v8.1：信用评级、规则树初始化、Agent不定期抽检与现金折扣
日期：2026-10-22（Asia/Shanghai）。编制：Codex。根据用户本轮连续指令修订。
状态：四项功能方向已由用户明确提出；以下为设计与候选实现，不代表评分权重、折扣上限、抽样参数已批准，亦不代表平台已部署。
作为原v8的增补文件，与两份规格裁决共同使用；不覆盖原稿，不改原始行业样例。
“汇款”本版先按客户回款/应收解释；对外汇款可扩展交易对手核验，借款指本企业借款/融资。若业务对象有差异，按对象类型调整，不把付款方评级与本企业评级混在一起。

## 1. 最终体验
企业首次进入 → 回答经营事实并授权提供数据 → 规则树推荐模板和待补指标 → 真实数据计算 → 结合信用信息提出处理候选 → 比较现金折扣、正常催收和借款融资 → 人工批准后执行 → 核验实际到账 → Agent按风险事件或随机窗口选样复核 → 留痕并跟进。
核心仍在千问办公运行；Python只提供离线原型和对照自测。样例仅调试，最终验收使用有来源的真实企业/上市公司数据，缺数据的步骤明确阻塞。

## 2. 两类真实数据必须分开
A. 企业授权经营明细：逐笔现金流水、应收、合同、银行流水、授信、借还款计划及必要凭证。可支持明细核对和周度预测，但前提是期间与字段完整且公式批准。
B. 上市公司披露：保留原公告/报告链接或原件、报告期、公告日期、页码或表名、币种、单位、合并/母公司口径及是否重述。按真实披露频率计算，不用年报/季报反推出逐笔汇款、客户实际付款日、银行确认或完整13周预测。
不将缺乏客户明细解释为客户信用良好；不将上市身份自动视为高评级。不混用同一企业不同口径报表、不把累计季度数当单季数；口径不齐不强行拼接。回测只使用当时已公开的信息，防止未来公告数据泄漏。

## 3. 信用评级：评价对象与证据
- 回款客户：可追溯付款/逾期历史、账龄、合同履约、有效外部评级等。
- 本企业借款：实际负债、还本付息计划、已批准财务指标、融资合同及有效评级。
- 融资机构可靠性如需评价，另列对象，不能拿银行机构评级代替本企业获贷概率。
外部评级保留评级机构、评级对象/债项、原等级尺度、日期、展望及来源。内部规则评级明确标内部，不冒充外部评级。缺失、过期、对象不匹配单列待核；不同机构等级不可直接混排。
评分权重、分界、有效期、信用到回款概率/融资可用额度的映射均须有批准版本；未经批准不输出虚构概率或自动折算系数。
评级不改变已验证的真实到账金额，不自动核减或增加债务，不替代银行确认，不直接覆盖既有Q/D/FUSE或现金灯。未完成信用评估时，原指标结果与“信用信息不足”并列展示，不称整体信用安全。

## 4. 规则决策树生成初始配置
先用可解释规则树，不先训练没有标签依据的机器学习模型。五题沿原方案：主营业务、主要成本、回款周期、资金来源、淡旺季。
输出推荐行业模板、候选指标/字段、信用核实重点、季节性数据需求与每一步答案来源。混业/其他/答案缺失应追问，不硬塞行业。
区分三件事：指标字段清单、真实财务指标值、数值型阈值。规则树能推荐第一项；第二项由真实数据和公式算；第三项只能来自批准模板/校准，不靠问卷生成营收、K、信用等级或预测。
当前模板四个JSON为{}，故原型所有数值初始参数保持null。正式启用要绑定批准模板版本、数据期间及确认人。
纠正原文组合口径：前四题各5选项，第五题2选项，共5×5×5×5×2=1250，不是3125。原型枚举1250种输入不等于验证1250家企业，更不代表模型准确率。

## 5. Agent不定期抽检
不替代日常巡检，新增两类触发：已批准风险事件触发、授权时间窗内随机触发。不是后台无限轮询，也不是让Agent随意挑对象。
抽检对象可包括回款凭证、借款合同与还款节点、评级来源、现金折扣审批及到期处理。范围、金额门槛、随机比例、时间窗、冷却期、重抽规则、负责人和升级条件均配置化，数值未批则显示未配置，不假装已抽检。
选样时冻结候选池、记录算法版本和样本清单，支持审计复现；同次触发用稳定批次标识防重。风险优先和随机样本分开标注，不能用风险样本结果推断总体问题率。
Agent可按授权选样、读取可访问证据、指出差异、创建待办及形成报告；证据真实性由可信银行/已认证复核记录等确认，不自行给自己审批。
记录触发原因、样本范围、源记录、检查项、证据、复核人、结论和处理结果。未查、查中、证据不足、通过、异常作为本模块工作流概念，最终字段枚举须契约审定；不是数据闸新增词。
原v8凭证20%抽检条款与不定期触发不是同一参数。保留原条款供核对，不默认将20%扩到合同/评级/折扣；新方案也不能使未被抽中的凭证自动成为verified。
平台不支持后台触发或定时器时，明确只能手动发起，不能声称已具备不定期自动抽检。当前不创建任何真实定时任务。

## 6. 加入现金折扣处理机制
目的：在回款时点和让利成本之间做有证据的方案比较，而不是一有缺口就借款或给客户打折。
现金折扣区别于贸易折扣、坏账核销、保理融资、借款利息减免。供应商早付折扣可以作为另一方向比较，但借款提前还款的利息/费用按借款合同另算，不能套应收折扣公式直接减本金。
候选方案必须包含：客户/合同/单据、折扣基数及其含义、折扣率、币种、截止日、基线预计到账日、折扣后预计到账日、审批依据、条款版本、舍入与税务/会计处理依据。
不要把已经按净额记录的账面应收再打一次折；名义合同金额、账面余额、已批折扣、预计净收和实际到账分别保存。先限定无争议、基数可确认的样例；争议、红字、退货、部分付款先按批准规则处理。

### 6.1 方案比较的算式（候选，正式值待WB-FIN审定）
设可确认折扣基数A、折扣率d、较可核实的基线提前天数t：折扣额=A×d，预计净收=A×(1-d)。d以0.02表示2%。
以365天演示时，简单年化资金成本=d/(1-d)×365/t；复利年化资金成本=(1/(1-d))^(365/t)-1。两种口径分别标注，不能直接拿单利折扣成本和另一种复利贷款利率混比。计息天数、日期基线、舍入和融资比较口径正式使用前须批准。
t为实际预期收款时点的提前量，不一定等于合同信用期减折扣期；t<=0不声称有提前回款收益。缺融资成本或回款概率依据，不自动判“值得”。
折扣成本、贷款利息及费用、流动性改善、可证实的回款不确定性和利润影响分别展示，避免把同一融资节省重复相加。信用较差不等于应给更大折扣；报价须通过授权、合同和企业限额约束。
现金路径将原预计回款移到新日期并改成净收，不能两周各计一次；借款方案则单列到账、利息、费用和还款，不把借款当营业回款。只有有明细与批准13周规则才能重算13周影响。

### 6.2 审批、实际到账与结算
Agent给候选，批准者通过可信流程批准，获授权人员与客户确认。Agent不能擅自对外承诺折扣、修改发票、放款或划款。
正常示例（虚构）：原应收100万元，获批且满足条件的2%现金折扣为2万元，应净收98万元。银行实际到账记录98万元，折扣另记2万元；不把已收金额写成100万元，也不把折扣2万元计入现金。
比对时必须先核实批准条款、期限、适用单据、是否已经使用/撤销、实际到账证据，再将实际净到账与生效应净收核对。不能只见98万元就认定“合法折扣”，也不能用口头“有折扣”绕过金额不符。
当前verify_payment仍基于现行契约，不具备折扣证据映射前，只能报告待核实，不能返回verified。新增结算语义须同步契约、公式、服务验证和测试，不悄悄改现有严格比对。现有gate_闭集不增词；有批准折扣的解释单列，不自动覆盖旧样例或约28处正常部分到账。
会计分录、税额/发票、应收冲减方式按适用准则、合同和企业政策另行确定。本修订是现金管理机制，不直接生成入账分录。

## 7. 与现有系统的接入边界
暂不擅自改变14工具、24event_type及11表集合。先评估现有JSON快照能否承载评级引用、抽样计划和折扣条款引用，涉及新增表/字段/状态/工具的候选另行审定，不宣称现有工具已支持。
审计事件优先选真实语义匹配且已批准的audit_triggered、task_result等，不凭空新增credit_rating或cash_discount枚举。评级及折扣不能由模型参数自证批准。
Agent新增能力为画像问答、评级解读、折扣/借款候选比较、不定期抽检与跟进。具体计算仍按批准架构在千问表格，工具只提供受控接口与RF例外。

## 8. 分工与验证
Codex负责本修订、离线规则树和折扣算术原型；WorkBuddy在WB-FIN后续版本补公式/数据需求及实现候选，DeepSeek独立审查。千问仅必要平台接入与调试。所有任务按总看板串行。
至少验证：评级缺失/过期/对象不符；1250组合及缺答案；审批与未审批折扣；折扣截止日边界；不符合折扣仍少付；真实部分到账；付款超过期限；折扣已被用过；原应收已净额记录；t<=0；金额舍入；跨周不重复；抽样池为空/重复触发/平台离线/复核身份缺失；上市公司明细不足。
真实企业与上市公司必须来源可核对、结论可追溯。当前离线原型并未评价任何真实企业，也未做千问实测。
