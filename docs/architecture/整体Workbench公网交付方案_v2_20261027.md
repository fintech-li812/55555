# 整体 Workbench 公网交付方案 v2
日期：2026-10-27。用户最新要求：前端与整套工作流组成一个Workbench，任何访客可通过千问托管网址打开；最终交付为网页应用。

## 整体产品
一个千问托管的动态网站是唯一用户入口。界面包括数据来源与校验、现金流分析、余额核对、报告与记录、AI助手和运行状态。用户无需安装本机技能、连接器或Python。
界面背后统一由服务端管理工作流、身份和计算：网页 → 同源业务接口 → Python计算/工具编排 → MySQL与工件记录。Agent调用同一套业务工具，不另做金额计算。
访客不直接访问MySQL、MCP stdio或本机D盘；千问聊天会话里的连接器不会自动成为网页权限。

## 首次发布范围
先发布完整合成演示来源synthetic_eight_sheet_v1，保留明确SYNTHETIC标识。访客可体验已登记数据的检查、真实程序计算、三类汇总、余额核对和报告下载。
保存/历史查看须有服务端受控会话及隔离范围；真实企业上传、多人数据和后台管理不能在未实现时显示成功。第一版没有通用Excel导入时不做虚假上传入口。
AI助手必须通过网页服务端的实际模型/工具接口接入；没有平台桥接或模型配置时如实标记未接通，不能放一个假聊天框。
保持原始埋错样例私有。不要向公开站点上传既有账户资料、原项目全目录、SSH私钥或数据库口令。

## 云端部署
1. 千问Pages承载动态前端及同源接口层；官方当前说明动态后端为Node.js。
2. 现有Python引擎需要真正的云端运行环境和可被服务端调用的API，或经实测存在的平台MCP桥接。不能把127.0.0.1/D盘路径写进公网应用当远端地址，也不能假定平台支持Python。
3. 已有MySQL在云端，继续保持内网/回环访问。公开业务服务使用应用账号和限定权限，不把现有本机root隔离QA连接直接暴露为公共服务。
4. 网页服务端统一处理认证、授权、输入大小、允许来源、请求幂等、超时和错误。前端不持有后端密钥。
5. 现有SSH本机联调保留作调试；最终网址不依赖开发者电脑常开。
6. 若平台MCP桥接不可用，须先提供经过鉴权和传输保护的云端计算API；未接通前只能称预览，不称整套Workbench上线。

## 工作流与接口职责
- 选择来源 → 来源登记/摘要 → 已列校验 → 不通过则定位原格并阻断。
- 校验通过 → 服务端实际计算 → 返回来源、算法、三类金额、独立余额差异。
- 用户确认保存 → 服务端使用稳定request_id保存 → 精确回查 → 页面显示回执与核对。
- 报告下载取自本次结果，失败时清空旧状态，不用写死数字填充。
- AI助手组织这些同一业务动作，所有金额取自工具；权限和租户由服务端会话确定，不信任浏览器/模型自填身份。

## 发布验收
必须通过实际*.qwenwork.host网址访问，验证页面可打开、服务端真算、错误路径、保存/回查归属、刷新后历史和报告来源。部署失败或后端不可用要如实显示。
合成基准：期初100000、流入185000、流出108000、净额77000、期末177000、差异0；该数据仅为断言，不作为硬编码界面数据源。
交付URL、部署版本、源代码包、运行/恢复说明、测试证据和未完成项。保留历史版本，不覆盖生产数据。
