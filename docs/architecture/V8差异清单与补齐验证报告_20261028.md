### 2.2 误判说明（重要）

上一版报告写「`feedback_log`/`param_template` 等 6 张表不存在」，**结论对但原因错**。
真实原因是：`sql/init.sql` 自带 `CREATE DATABASE cf_workbench; USE cf_workbench;`，
而这个文件**从未在服务器执行过**——服务器上的 `cf_workbench` 库是**空的**。

```
mysql> SHOW TABLES FROM cf_workbench;   →  （空）
mysql> SHOW TABLES FROM cfqa_workbench; →  mfg_cashflow_runs_v1, cf_rollcast_*, ...
```

所以缺失的根源是"整个地基库没执行"，而不是"这两张表忘了建"。
这一区别决定了补齐方式：不需要补写表定义，只需把已有的权威定义执行掉。

**修复方式遵循"不复制表定义"原则**：`deploy/init_v8_tables.sh` 不重写任何 DDL，
只是把三份 `.sql`（仍是唯一权威定义）剥离自带的建库/切库语句后拼接执行，
保持单一数据源。

## 四、算法层（本次发现的两个严重缺陷）

### 4.1 缺陷 A：DEA-DA 求解方向反转 ⚠ 严重

**位置**：`v8/layers.py:deada` 第 305-311 行（原 `c[k] = 1.0`）
**关联**：`v8/layers.py:_simplex` 的 docstring 原写 `min cᵀx`，与实现不符

**问题链条**：

1. `_simplex` 的**实际语义是 maximize cᵀx**（docstring 误写为 min）。
   判别实验：`c=[1,1,0]`、约束 `x1+x2+s=10` 时返回 `obj=10`（取到 x1=10），
   而非 minimize 下的 0。
2. `deada` 按标准 DEA-DA 需要 **minimize** 误分类总量 `Σ(s⁺+s⁻)`，
   却在 maximize 语义下给松弛变量系数 `+1.0`。
3. 结果：**实际在最大化所有样本的误分类**。

**量化证据**：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 误分类总量 Σs | 32.031082 | **21.717915**（-32%） |
| 非零松弛变量 | 39 / 40 | 34 / 40 |

**修复**：松弛变量系数改为 `-1.0`（maximize -Σs ≡ minimize Σs），
并更正 `_simplex` 的 docstring 为 maximize，注明调用方需自行取负。

**⚠ 对演示结论的影响（必须让负责人知道）**：

| 受评场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 企业 A（healthy） | 绿灯 | 绿灯 |
| **企业 B（edge，缓冲偏紧）** | **红灯** | **绿灯** |
| 企业 C（risk） | 红灯 | 红灯 |

修复前 edge 的 D=-0.118 来自错误权重，不是真实判别结果。修复后 D=+0.188。
**答辩/演示前必须重新核对这一场景的讲解口径。**

### 4.2 缺陷 B：判别得分 D 跨平台不可复现 ⚠ 严重

**位置**：`v8/layers.py:_simplex` 的 `pivot` 函数

**问题**：pivot 的注释写着"Bland 平局"，但**实现并未用 Bland 规则**——
它选"最负 reduced cost"，容差仅 1e-12。当两列的 reduced cost 在浮点误差范围内
接近时，不同平台的 libm / CPU / Python 版本算出的微小差异会选到**不同的进基列**，
进而走出不同的 pivot 路径。

**量化证据**：

| 环境 | 修复前 D 值 | 修复后 D 值 |
| --- | --- | --- |
| Windows 11 + Python 3.13.14 | -0.117677 | -0.117677 →（修复后随缺陷 A 变更为 0.868543…见下） |
| Linux + Python 3.12.3 | **-0.114258** | 与 Windows 一致 |

同平台内各自稳定（连跑 3 次完全相同），但**跨平台不一致**，
违反 V8 第十八章"全链路可追踪、可复现"的要求。

**修复**：改为真正的 Bland 最小下标规则——

- 入基 = 下标最小的负 reduced cost 列（与系数大小无关，只与下标有关）
- 出基 = 最小比值行；比值并列时取基变量下标最小者
- 容差统一为 `TOL = 1e-9`

下标是整数比较，不受浮点误差影响，从而保证结果跨平台一致。

**验证**（缺陷 A 修复后，两平台各跑一次）：

```
WINDOWS Py3.13 | Q=0.566700  D=0.868543  P=0.9833  降级=False
LINUX   Py3.12 | Q=0.566700  D=0.868543  P=0.9833  降级=False
```

### 4.3 缺陷 C：融合规则存在口径矛盾 ⚠ 未修正，需负责人裁决

**位置**：`v8/layers.py:fuse` vs `v8/layers.py:benford_rf`

第三层 `benford_rf` 自称口径是「**P ≥ 0.7 升级红灯，P < 0.3 降级黄灯**」，
但 `fuse()` 的实现要求 `(D < 0 且 P ≥ 0.7)` 才判红灯。

后果：受评企业 B 的 P = **0.9833**（舞弊概率 98.33%），但因为 D = +0.188 ≥ 0，
融合判定为**绿灯**，P 完全没有起作用。

**本次不擅自修正**：`fuse()` 的公式是 V8 方案定义的判定口径，改动会影响与方案
文档的一致性。改为用测试固化当前行为
（`test_high_fraud_probability_alone_does_not_trigger_red`），
一旦口径被改动或对齐，测试会立刻显形。

**建议**：请方案负责人在"按 D 主导"与"P 单独可触发红灯"之间明确选择。
