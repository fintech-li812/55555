## 二、风控规则与模型

### 2.1 三层风控模型（截面判定核心）

三层是**串行证据链**：第一层的数据质量决定后两层结论是否可信；来源优先级 **Q > D > P**。

#### 第一层：数据质量门禁 → 质量得分 Q

- **方法**：BM-BP 双质量因子（杨贵军等，2022《统计与决策》）
- **Benford 律首位数字 χ² 检验**：对 15 个财务比率逐一检验，χ² > 20.09（10% 显著性，df=8）判"偏离"，记录偏离最大的首位数字为"风险数字"，命中记 B 因子=1
- **末位数字检验**：Myer 混合指数 M = 0.5×Σ|P1j−P2j|（按值大小分两组比较末位分布，文献判据 M>20）。**工程取舍**：Myer 对小样本敏感，数值照算但只作展示；"末位堆积"改用末位数字对均匀分布的 χ² 检验（df=9，5% 临界 16.92），命中记 M 因子=1
- **得分公式**：`Q = 1 − (ΣB + ΣM) / (2 × 指标数)`，越接近 1 质量越高

#### 第二层：财务健康判别 → 判别得分 D

- **方法**：改进 DEA-DA 两阶段判别（马秀颖等，2026《数理统计与管理》，BCC 规模收益可变）
- **流程**：
  1. 前处理：逆指标取负（AR_DAYS、X13 资产负债率），使全部投入满足"越大越好"
  2. 按列 z-score 标准化消除量纲
  3. 两阶段单纯形法（自实现 `_simplex`，零外部依赖）求解线性规划：**最小化误分类总量 min Σ(s⁺+s⁻)**，约束 Σv+Σu=1 归一化
  4. `D = (Σv·投入 + Σu·产出) − 临界值`；**D < 0 判为财务风险**
- **降级机制**：LP 未求得最优解 → 降级为等权判别，返回 `降级=True`，融合层据此将 D 视为不可用

#### 第三层：异常样本复核 → 舞弊概率 P

- **方法**：Benford-随机森林（孙玲莉等，2021《数量经济技术经济研究》）
- **特征**：15 个财务比率 + 15 个 Benford 因子（该样本首位数字是否命中第一层风险数字）= 30 维
- **模型**：自实现 CART 决策树（Gini 分裂，max_depth=4）+ bootstrap 随机森林，n_trees=60
- **输出**：各树叶子概率的平均投票 P ∈ [0,1]；`树数=0` 时 P 无意义（不可当 0.0 用）

### 2.2 融合判定 FUSE(Q, D, P) —— 唯一权威实现 `v8/fusion.py`

互斥且完备的 48 格决策表（|Q|=4 × |D|=3 × |P|=4，无重叠无空洞无兜底，未命中直接抛错）。每个输入先离散化，**空值/非数值/越界/上游降级一律显式纳入判定**，"无法判断"绝不静默当作"无风险"。

| 规则 | Q | D | P | 等级 | 依据要点 |
|---|---|---|---|---|---|
| R1 | 缺失 | * | * | 红灯 | 门禁失效，无法支撑任何结论 |
| R2 | <0.3 | * | * | 红灯 | 质量严重不足，后两层不再参与判定 |
| R3 | ≥0.3 | 缺失 | * | 黄灯 | DEA-DA 不可用/降级，按存疑处理 |
| R4 | ≥0.3 | 风险(D<0) | 高(≥0.7) | 红灯 | 财务风险叠加疑似粉饰 |
| R5 | ≥0.3 | 风险(D<0) | 中/低/缺失 | 黄灯 | 经营性问题；P<0.3 排除粉饰则降级黄灯 |
| R6 | ≥0.3 | 正常(D≥0) | 高(≥0.7) | 黄灯 | **结论冲突，不放行绿灯，转人工复核**（唯一行为变更点） |
| R7 | [0.3,0.5) | 正常 | 中/低 | 黄灯 | 未达绿灯门槛 Q≥0.5 |
| R8 | [0.3,0.5) | 正常 | 缺失 | 黄灯 | 质量不达标且证据链不完整 |
| R9 | ≥0.5 | 正常 | 缺失 | 黄灯 | 证据链不完整 |
| R10 | ≥0.5 | 正常 | 中/低 | 绿灯 | 三层证据一致支持健康 |

> 历史遗留：`model/现金流风控_v2/risk_model.py:legacy_fuse` 保留旧灯色逻辑仅作向后对比，与 v8 唯一已知差异即 R6 场景（legacy 判绿灯），由 `tests/test_fusion_rules.py` 显式固定防漂移。

### 2.3 缓冲相对阈值判定（第二判定维度）

- **口径**：预警线 = 月均经营性流出 M × 行业系数 K（相对指标，随企业规模自动缩放），取代绝对金额
- 判定：缓冲倍数 = 期末现金 ÷ M；**< K红 → 红灯；< K黄 → 黄灯；≥ K黄 → 绿灯**
- **动态阈值**（`industry.py:dynamic_thresholds`）：历史缓冲倍数满 12 个月 → K黄=P25、K红=P10 滚动分位数；不足则回退静态并写明原因（不静默降级）。**注意：当前线上调用未传 history，实际用的都是静态阈值**（见 §7）

### 2.4 最终等级 = 两维度取较严格者

`engine.assess()`：`最终等级 = max(严格度)[FUSE 等级, 缓冲判定等级]`。参与比较的等级必须是已知灯色，缓冲维度缺失时如实标注"最终等级仅由三层融合给出"，不宣称两层并行。

### 2.5 配套机制（v8 engine 内）

- **压力测试**（四场景，相对缓冲倍数口径）：回款冲击（应收延迟 30 天）/ 融资冲击（授信缩减 50%）/ 成本冲击（成本上涨 20%）/ 联合冲击；冲击后再按 M×K 判级，最坏情况为红灯则触发紧急任务
- **三态跟踪**：待验证金额不计入现金缓冲，验证通过才纳入；已化解(绿)/观察中(黄+倒计时)/已恶化(红+提醒)
- **例外审批回溯**：部门例外率 > 20% → 异常偏高触发审计；连续 3 次理由相同且长度<10 → 理由敷衍；例外金额 > 季度预算×15% → 金额异常
- **分级审批**：金额 ÷ 月均业务规模 r；r ≤ 分界线1 → 部门经理；≤ 分界线2 → 财务总监；否则双签（财务总监+总经理）

### 2.6 13 周蒙特卡洛现金流引擎（model v2）与滚动预测（rollcast）

`cashflow_risk(data)`：
- 输入：13 周毛收/付款、总现金、受限现金、承诺授信、最低缓冲、≥26 周**历史预测误差**（实际−当时预测，成对）
- 模拟：循环移动块自助法（block_length=4，默认 5000 次），保持局部时序与收支相关性；授信额度只加一次
- 五项数据质量闸（对账/去重/完整性/时效/单位）任一失败 → 直接"待复核"不计算
- 压力测试：回款折损 20% / 付款上浮 10% / 回款延迟 2 周（可配）
- 校准包络：`calibrated_path_lower_bound` 用成熟预测起点的 split conformal 思路求同时性下包络（时间序列上仅为经验覆盖）
- 判级：基准容量跌破缓冲或情景缺口率 ≥ 红阈值(0.30) → 红灯；≥ 黄阈值(0.10) 或压力路径破线或未真实验证 → 黄灯

`rollcast/`（63 项测试）：把上述单次模拟扩展为 walk-forward 滚动预测，修复三处偏差——块长与业务周期冲突（累计误差标准差 1.55x→1.02x）、误差均值漂移（13×μ）、无样本外评测（名义 90% 区间实际覆盖 91.5%）；增量更新 26.1x 提速；t 分布 p 值自实现（与 scipy 对照误差 1.7e-15）。

## 四、风险评分与决策逻辑（汇总）

```
Q ∈ [0,1]   数据质量得分    = 1 − (ΣB + ΣM)/(2×15)
D ∈ ℝ       财务判别得分    = (Σv·投入 + Σu·产出) − 临界值    （D<0 → 风险）
P ∈ [0,1]   舞弊概率        = 随机森林 60 树平均投票
FUSE(Q,D,P) → 红/黄/绿      （48 格决策表，见 §2.2）
缓冲判定(缓冲倍数 vs K红/K黄) → 红/黄/绿
最终等级 = max 严格度(FUSE, 缓冲) ；等级 ∈ {红灯, 黄灯, 绿灯, 待复核}
```

外部动作（钉钉推送等）一律 dry-run / 不自动执行；`external_action_executed` 恒为 False 由内核保证。

## 五、各算法输入输出及调用关系

### 5.1 调用链（一次完整评估 `engine.assess(industry, scenario, amount)`）

```
v8_server /api/v8/assess
  └─ engine.assess()
       ├─ cashflow_facts() ──→ program_workbench.calculate('synthetic_eight_sheet_v1')
       │                        输入: 合成八表(冻结)  输出: 期末现金/期初现金/净额/M/三类净额/对账状态
       ├─ indicators.build_sample_pool(20)   输入: 无(种子 20261027)  输出: 40 样本×15 比率×label
       ├─ layers.quality_gate(pool)          输入: 样本池  输出: Q + 15 指标 Benford/Myer 明细(含风险数字)
       ├─ layers.deada(pool, target)         输入: 样本池+受评值  输出: D/权重/临界值/降级标志
       ├─ layers.benford_rf(pool, target, gate)  输入: 样本池+受评值+第一层风险数字
       │                                       输出: P/树数/特征构成
       ├─ fusion.fuse(Q, D, P, d_reliable, p_reliable)  输出: 等级/依据/规则ID/状态
       ├─ industry.judge_by_buffer(industry, M, buffer)  输出: 缓冲等级
       ├─ 取严 → 最终等级
       ├─ industry.warning_lines()  输出: 黄灯线/红灯线 (M×K)
       ├─ engine.stress_test()      输入: STRESS_INPUTS  输出: 四场景+最坏情况
       ├─ industry.approval_route() 输出: 审批人/要求
       └─ tracking_states() / exception_review()  输出: 三态记录 / 例外统计
  输出 schema: mfg-v8-risk-assessment.v1
```

依赖方向：`fusion` 依赖 `(Q, D, P, d_reliable, p_reliable)`；`benford_rf` 依赖 `quality_gate` 的风险数字（第一层输出喂第三层特征）；`engine` 是唯一编排入口。v2 引擎 `cashflow_risk` 独立成 CLI（输入 JSON → 输出 JSON+sha256 指纹）。

## 七、已发现的问题与可优化点

### 7.1 已修复（保留背景，避免优化时误判为现存问题）

1. **DEA-DA 求解方向反了**：`_simplex` 实为 maximize，原松弛变量系数 +1 等于最大化误分类（松弛总和 32.03，39/40 非零）→ 已改 −1.0
2. **单纯形跨平台不可复现**：最负 reduce cost 选列受浮点误差影响（Windows D=−0.117677 vs Linux −0.114258）→ 已改 **Bland 最小下标规则**（整数比较，跨平台一致）
3. **融合规则 15 处口径冲突**（阈值 0.5/>0.7/≥0.7 三种、规则不互斥靠 if/elif 顺序、空值崩溃、D 降级被忽略、树数=0 时 P=0 被当"排除粉饰"、前端 0.7 vs 文档 0.5 等）→ 已重构为 48 格互斥完备决策表 + 显式可用性输入，33+33 用例双平台通过
4. **Myer 指数小样本虚高** → 判据改末位均匀分布 χ²，Myer 仅展示
5. **rollcast 三处偏差**（块长与 7 周周期冲突放大 1.55x、误差均值漂移、无样本外评测）→ walk-forward 化
6. v2 首位/末位数字提取用 Decimal 防浮点舍入误差；金额单位显式单一

### 7.2 现存问题与可优化点（Codex 优化的主战场）

**A. 统计与模型层面**

| # | 问题 | 现状 | 优化方向 |
|---|---|---|---|
| A1 | **全部训练/演示数据为合成**，15 比率来自固定种子生成，风险组粉饰痕迹是人为构造 | 无真实企业数据 | 接真实数据是最大缺口；合成数据上的 Q/D/P 结论不能外推 |
| A2 | 样本池仅 20+20，Benford χ² 与 Myer 检验在小样本下功效不足（χ² 期望频数条件 n×p.min()≥5 在 40 样本×首位 9 格下常不满足） | v8 layers 未做 v2 的 Monte Carlo 精确检验回退 | 移植 v2 的期望频数判断 + 多项 MC 精确 p 值 |
| A3 | χ² 临界值 20.09/16.92 硬编码，显著性水平（10%/5%）不一致且未暴露为配置 | 硬编码 | 统一显著性口径，配置化；或改用 p 值判定 |
| A4 | RF 是自实现 CART（无特征子采样、无类平衡、无 OOB、无概率校准），P 是叶子频率平均，未经校准 | 60 树 depth4 | 特征 bagging（30 维只全量扫）、类别权重、Isotonic/Platt 校准、OOB 评估 |
| A5 | DEA-DA 自实现单纯形较慢且无对偶/灵敏度信息；第二层只用 8 个指标（4 投入 4 产出），CORE7 与 DEADA 指标集不一致（CORE7 未见使用） | CORE7 定义了但 deada 未用 | 明确 CORE7 的用途或删除；考虑 scipy.optimize.linprog（HiGHS）求解并保留降级路径 |
| A6 | `benford_rf` 的 Benford 因子依赖第一层**训练池**的风险数字，受评样本的因子定义与训练分布耦合 | gate 由池生成 | 复核因子构造的稳定性（风险数字随池波动） |
| A7 | 阈值 K黄/K红 为方案预设（P25/P10），无逐项出处/年份/样本量/页码 | THRESHOLD_SOURCE 统一标注 | 逐项溯源；上线前按最新年报重核 |
| A8 | **动态阈值已实现但未接线**：`judge_by_buffer` 支持 history 参数，engine 调用时未传，线上全为静态 | B3 未启用 | 把企业历史缓冲倍数从库中取出传入 |
| A9 | 两个时间引擎（v2 13 周 + v8 缓冲倍数）与截面三层模型之间**无联合输出**，各说各话 | 分离 | 统一风险视图/组合评分 |

### 7.4 进展（2026-10-29）：算法候选 ra-next-0.1 已接入

Collex 交付 `algo/RA_NEXT/`，工程侧已完成适配与联调，**双版本并存、默认仍走基线**。

| 项 | 变化 |
|---|---|
