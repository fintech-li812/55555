## 1. 拓扑

```
千问办公（Windows 笔记本 · Agent / 定时任务 / 千问表格）
        │  局域网 HTTP(S) → /mcp
        ▼
2 核 2G 服务器（常开）
        ├─ Nginx（可选反代 + 内网 allow + 令牌透传）
        ├─ MCP Server :8000（FastAPI + MCP SDK + scikit-learn 推理）
        └─ MySQL :3306（只绑 127.0.0.1，不对局域网与公网暴露）
```

关键约束（协议 §3.3）：MySQL 不对公网暴露；MCP 入口必须有鉴权；企业条件由服务端从已认证主体解析。

## 2. 2G 内存预算（这台机器的真正瓶颈）

| 组件 | 常驻估算 | 必做的调优 |
|---|---|---|
| 操作系统 + sshd | 250~300 MB | — |
| MySQL 8.x | 400~500 MB | `innodb_buffer_pool_size=256M`、`max_connections=20`、按需关 `performance_schema` |
| MCP Server（Python + FastAPI + MCP SDK） | 120~180 MB | uvicorn 单 worker 即可，本方案并发极低 |
| scikit-learn 随机森林 | 50~150 MB | **懒加载**模型；`n_estimators ≤ 200`；用 `joblib.load(mmap_level=3)` |
| Nginx（若已有） | 5~15 MB | — |
| **合计** | **约 1.0~1.2 GB** | 留 ≈0.8 GB 余量 |

三条硬性建议：
1. **必须配 swap**（2 GB），否则 sklearn 模型加载 + mysqldump 同时发生时会 OOM。
2. `rf_predict` 模型**常驻不重载**：进程启动后台预热一次，避免每次调用反序列化。
3. 若这台机器上还跑着网站应用（PHP/Java），把它的内存上限告诉我，需要重算预算——2G 同时扛网站 + MySQL + Python 推理是紧的，必要时把网站挪走。

## 3. 服务器侧安装

### 3.1 MySQL

```bash
# 仅当 F3 确认未安装时执行（Debian/Ubuntu 示例，待 F1 校正）
sudo apt update && sudo apt install -y mysql-server
sudo systemctl enable --now mysql
mysql --version
```

确认只监听回环：

```bash
sudo grep -R "^bind-address" /etc/mysql/ 
# 期望：bind-address = 127.0.0.1
sudo ss -lntp | grep 3306    # 期望只有 127.0.0.1:3306
```

### 3.2 建库与三账号（按裁决 D6 拆分，不用 v8 的 GRANT ALL）

```bash
sudo mysql -e "CREATE DATABASE cf_workbench CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;"
# 口令只写进环境变量 / systemd Environment，不落文档、不落仓库
sudo mysql <<SQL
CREATE USER 'cf_admin'@'localhost'  IDENTIFIED BY '${CF_ADMIN_PW}';
CREATE USER 'cf_app'@'localhost'    IDENTIFIED BY '${CF_APP_PW}';
CREATE USER 'cf_backup'@'localhost' IDENTIFIED BY '${CF_BACKUP_PW}';
GRANT SELECT, INSERT ON cf_workbench.* TO 'cf_app'@'localhost';      -- 运行账号：不给 UPDATE/DELETE/DROP/ALTER
GRANT CREATE, ALTER, DROP, INSERT, SELECT, REFERENCES ON cf_workbench.* TO 'cf_admin'@'localhost';  -- 迁移与模板发布
GRANT SELECT, LOCK TABLES, SHOW VIEW, TRIGGER, PROCESS ON cf_workbench.* TO 'cf_backup'@'localhost';
FLUSH PRIVILEGES;
SQL

# 表结构（待 sql/init.sql 定稿后执行）
sudo mysql cf_workbench < sql/init.sql
```

### 3.3 MCP Server

```bash
sudo apt install -y python3-venv
cd /opt && sudo mkdir -p cf-mcp && cd cf-mcp
python3 -m venv venv && ./venv/bin/pip install -r requirements.txt
```

`/etc/systemd/system/cf-mcp.service`（口令走 EnvironmentFile，不进代码库）：

```ini
[Unit]
Description=Cashflow Risk Workbench MCP Server
After=network-online.target mysql.service

[Service]
User=cfmcp
EnvironmentFile=/etc/cf-mcp/env        # CF_DB_HOST=127.0.0.1 / CF_DB_USER=cf_app / CF_DB_PW=... / CF_TENANT=demo01
ExecStart=/opt/cf-mcp/venv/bin/uvicorn app:app --host 127.0.0.1 --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now cf-mcp
curl -s http://127.0.0.1:8000/mcp -o /dev/null -w "%{http_code}\n"   # 期望 405/200，非 000
```

### 3.4 Nginx（仅当 F4 为"已有"；这是推荐的最小暴露做法）

```nginx
location /mcp {
    allow 192.168.0.0/16;   # 换成你的内网段
    deny all;
    proxy_pass http://127.0.0.1:8000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header Upgrade $http_upgrade;      # SSE 需要
    proxy_set_header Connection "upgrade";
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_buffering off;                          # 用 SSE 时必须关缓冲
    proxy_read_timeout 3600s;
}
```

防火墙：只把 80/443 放行给内网段；**8000 与 3306 一律不对外**。

```bash
sudo ufw allow from 192.168.0.0/16 to any port 443 proto tcp
sudo ufw deny 8000 && sudo ufw deny 3306
```

## 4. 千问办公连接器配置

自定义 MCP → Streamable HTTP，两种写法按 F4 选：

| 场景 | URL | Headers |
|---|---|---|
| 有域名+证书 | `https://<域名>/mcp` | `Authorization: Bearer <令牌>` |
| 纯内网直连 Nginx | `http://<内网IP>/mcp` | `Authorization: Bearer <令牌>` |
| 无 Nginx 临时联调 | `http://<内网IP>:8000/mcp` | 同上，且必须靠防火墙白名单兜底 |

> ⚠ **v8 §8.6 写"Headers: 留空"是不成立的**：协议 §3.2 要求鉴权在 initialize 及后续调用全程生效。留空等于把写审计库的能力交给任何能连到内网的人。

验证：添加后查询该自定义 MCP，状态应为 `connected`，工具列表应返回 **14 个**（协议验收 01）。

## 5. 与协议 §3.3 的偏差登记（答辩必须如实说）

| 协议要求 | 本部署实际 | 定性 |
|---|---|---|

## 6. 定时任务的真实边界（别让部署章节误导评委）

千问办公的定时任务在**笔记本**上执行，不在这台服务器上。所以：

- 服务器常开 → 保证**留痕可写、审计可查、多人可连**；
- 笔记本关机 → **每日巡检 / 月度压测 / 季度回溯都不会跑**。这条 v8 §1.2 已列为待验证，降级路径是"公司统一开机启动"或"手动触发 + 录屏"。
- 答辩演示建议：提前用手动触发跑一轮并留截图，不要宣称"服务器 7×24 无人值守自动巡检"。

## 7. 备份与恢复演练（v8 §8.7 要求做一次）

```bash
# /etc/cron.d/cf-backup：每日 03:00
0 3 * * * cf_backup mysqldump --single-transaction -u cf_backup -p"$_PW" cf_workbench | gzip > /var/backups/cf/cf_$(date +\%F).sql.gz
```

- 保留 7 天；**至少一份拉到笔记本异机存放**（同一台机器上的备份不算备份）。
- 恢复演练：`mysql cf_workbench < 某日备份` → 抽查 `audit_log` 行数与 `mcp_request_ledger` 幂等键一致 → 截图存档。
