# 数据库连接与开机自动建连（Ubuntu 24.04 + MySQL 8.0）

适用环境：生产主机（Ubuntu 24.04.5 LTS，systemd，MySQL 8.0.46）。
主机地址见部署侧配置（本仓库不保留真实地址）。
若你的发行版不是 Ubuntu、数据库不是 MySQL 或 init 不是 systemd，本文的路径与命令需要相应调整。

---

## 1. 数据库现状

| 项 | 值 |
|---|---|
| 数据库 | MySQL `8.0.46-0ubuntu0.24.04.4`（`mysql-server 8.0.46`） |
| 服务单元 | `mysql.service`（`enabled` + `active`） |
| 监听 | `127.0.0.1:3306`（另有管理口 `127.0.0.1:33060`）；`bind-address = 127.0.0.1` 且 `skip_name_resolve` 未开 → **只接受本机连接，不对外暴露** |
| 认证方式 | 应用账号 `caching_sha2_password`；`root@localhost` 用 `auth_socket`（只能由 OS root 免密登录） |
| 数据库 | `cfqa_workbench`（utf8mb4） |
| 应用账号 | `cf_app`，同时建了 `@127.0.0.1` 与 `@localhost` 两条 |
| 账号权限 | `SELECT, INSERT, UPDATE` on `cfqa_workbench.*`（最小权限，见 §5 说明） |

### 连接命令与预期输出

```bash
# 管理员验证（OS root 走 auth_socket，不需要口令）
mysql -e "SELECT VERSION();"

# 应用账号验证：口令写在临时 0600 的 client 配置里，避免出现在 ps 输出中
ENV_FILE=/opt/cashflow/deploy/.env bash /opt/cashflow/scripts/db_account_bootstrap.sh
```

预期输出尾部应有：

```
result      version                  db                user
连接成功    8.0.46-0ubuntu0.24.04.4  cfqa_workbench    cf_app@127.0.0.1

授权明细：
  GRANT USAGE ON *.* TO `cf_app`@`localhost`
  GRANT SELECT, INSERT, UPDATE ON `cfqa_workbench`.* TO `cf_app`@`localhost`
```

> 注：`root@localhost` 使用 `auth_socket`，所以**不要**给 root 设口令或改认证方式，
> 否则会把 `debian-sys-maint` 之外的维护通道搞坏。本方案全程只用应用账号。

## 2. 交付文件

仓库副本在 `deploy/linux/` 下，实际落位见"目标路径"列。

| 文件 | 目标路径 | 权限 | 作用 |
|---|---|---|---|
| `db_autoconnect.py` | `/opt/cashflow/scripts/db_autoconnect.py` | 0755 cfrun:cfrun | 连接程序：重试、日志、幂等、就绪标记 |
| `cf-db-connect.service` | `/etc/systemd/system/cf-db-connect.service` | 0644 root:root | 开机自启动单元 |
| `db_account_bootstrap.sh` | `/opt/cashflow/scripts/db_account_bootstrap.sh` | 0750 root:root | 账号/授权的幂等初始化（**仅 root 可执行**） |
| `profile-d-cf-db-autoconnect.sh` | `/etc/profile.d/10-cf-db-autoconnect.sh` | 0644 root:root | 每开一次交互式登录终端校验一次连接 |
| `logrotate-cf-db-autoconnect` | `/etc/logrotate.d/cf-db-autoconnect` | 0644 root:root | 日志按周轮转、保留 8 份、压缩 |
| `cf-db-connect.desktop` | （可选）`~/.config/autostart/cf-db-connect.desktop` | 0644 $USER | 桌面会话自启动项，**本服务器无桌面，默认不装** |
| `verify_db_autoconnect.sh` | `/tmp/`（一次性） | — | 行为验证脚本：并发/失败/重复执行/钩子 |

运行时产物：

| 路径 | 由谁创建 | 说明 |
|---|---|---|
| `/run/cashflow/db-ready` | 程序自身 | 就绪标记（JSON），原子替换写入 |
| `/run/cashflow/db-autoconnect.lock` | 程序自身 | `flock` 互斥锁，防止并发多实例 |
| `/var/log/cashflow/db-autoconnect.log` | 程序自身 | 日志，同时进 journald |
| `/run/cashflow`、`/var/log/cashflow` | systemd（`RuntimeDirectory`/`LogsDirectory`） | 每次启动重建，不依赖安装时手工 mkdir |

## 3. 启用命令（按顺序执行）

```bash
# 3.1 安装（已执行一次；重装时用同样的 install 保证权限不被覆盖）
install -m 0755 -o cfrun -g cfrun db_autoconnect.py            /opt/cashflow/scripts/db_autoconnect.py
install -m 0750 -o root  -g root  db_account_bootstrap.sh      /opt/cashflow/scripts/db_account_bootstrap.sh
install -m 0644 -o root  -g root  cf-db-connect.service        /etc/systemd/system/cf-db-connect.service
install -m 0644 -o root  -g root  profile-d-cf-db-autoconnect.sh /etc/profile.d/10-cf-db-autoconnect.sh
install -m 0644 -o root  -g root  logrotate-cf-db-autoconnect  /etc/logrotate.d/cf-db-autoconnect

# 3.2 账号初始化（幂等，可反复执行；可选 --allow-ddl）
ENV_FILE=/opt/cashflow/deploy/.env bash /opt/cashflow/scripts/db_account_bootstrap.sh

# 3.3 单元校验 —— 必须无告警，否则 systemd 会静默忽略掉写错段的键
systemd-analyze verify /etc/systemd/system/cf-db-connect.service

# 3.4 启用开机自启动
systemctl daemon-reload
systemctl enable  cf-db-connect.service     # 建 multi-user.target.wants 软链
systemctl start   cf-db-connect.service     # 立即跑一次
systemctl is-enabled cf-db-connect.service  # => enabled
```

停止/禁用：

```bash
systemctl disable --now cf-db-connect.service
```

## 4. 如何验证自启动确实生效

### 4.1 不重启的证据（已实测）

```bash
systemctl is-enabled cf-db-connect.service                 # enabled
systemctl show cf-db-connect -p After  --value             # 含 mysql.service
systemctl show cf-db-connect -p Before --value             # 含 cf-v8-web.service cf-workbench.service
ls -l /etc/systemd/system/multi-user.target.wants/cf-db-connect.service   # 软链存在
```

顺序的含义：`mysql.service` → **`cf-db-connect.service`** → `cf-v8-web.service` / `cf-workbench.service`，
即两个业务服务起来之前，数据库连接已经被校验过并留下就绪标记。

模拟"重启后 /run 被清空"：

```bash
systemctl stop cf-db-connect.service
rm -rf /run/cashflow                 # 模拟 tmpfs 清空
systemctl start cf-db-connect.service
cat /run/cashflow/db-ready           # 应重新生成，且 active
```

### 4.2 真正的开机自启动验证（需要重启，请自行安排窗口）

```bash
sudo reboot
# 重启后执行：
systemctl is-active cf-db-connect.service       # active
journalctl -u cf-db-connect -b --no-pager       # 本次启动的日志
cat /run/cashflow/db-ready
# 关键证据：就绪标记的时间必须早于两个业务服务的启动时间
journalctl -u cf-db-connect -b -o short-unix | head -3
journalctl -u cf-v8-web      -b -o short-unix | head -3
```

判定标准：`cf-db-connect` 的开始时间 < `cf-v8-web` 的开始时间，且日志里有
"第 1 次连接成功…就绪标记已写入"字样。

### 4.3 终端打开时的验证

```bash
rm -f /run/cashflow/db-ready
bash -c 'true'                      # 非登录 shell：不应触发
ls /run/cashflow/db-ready           # 不存在 → OK（脚本/scp 等不会被连库拖慢）
bash -lic 'true'                    # 交互式登录 shell：触发一次
cat /run/cashflow/db-ready          # 存在 → OK
bash -lic 'true'                    # 再开一次
tail -1 /var/log/cashflow/db-autoconnect.log
# => "... 就绪标记 Ns 前刚生成，视为新鲜，跳过连接。"
```

## 5. 设计要点与取舍

**凭证不硬编码。** 程序只从环境变量读；环境变量由 systemd 的
`EnvironmentFile=/opt/cashflow/deploy/.env` 注入，或手工运行时用 `--env-file`
从同一个文件读取——单一数据源，不存在两处口令需要同步。该文件已是
`0600 cfrun:cfrun`；程序与 bootstrap 脚本都会**先检查权限**，若组或其他用户
可读则直接拒绝执行（这一点很重要：凭证泄露往往发生在"顺手 chmod 644"之后）。
日志与 stdout 里永远不打印口令，异常信息里的口令会被替换成 `***`。

**重复执行无副作用。** 三层保障：

1. `flock` 独占锁：第二个实例直接返回退出码 4，不叠加进程、不并发写日志。
2. 就绪标记用「临时文件 + `os.replace`」原子替换，不会出现半行 JSON。
3. `--fresh-secs`：就绪标记在指定秒数（登录钩子用 300s）内视为新鲜，直接返回 0。

所以连开十个终端、systemd 重启多次，都不会重复连库或留下脏数据。
整个程序对数据库**只有读操作**（`SELECT 1` / `VERSION()` / `information_schema`），
即使反复运行也不会写入业务表。

**最小权限：为什么没有授予 CREATE。**
应用代码里有 `CREATE TABLE IF NOT EXISTS` 的自愈逻辑，但授予 `CREATE` 意味着应用
账号可以任意建表。取舍是：**运行时账号只给 `SELECT, INSERT, UPDATE`**，
建表明确属于管理员职责（`sql/v8_schema.sql`）。如果你希望保留应用自愈建表能力，
在 bootstrap 时显式加 `--allow-ddl`（会额外授予 `CREATE`），这是有意识的选择而非默认行为。

同理没有授予 `DELETE` / `DROP`：当前的留痕表是只增的。

**为什么不改现有业务单元。** `cf-v8-web.service` 与 `cf-workbench.service`
原本就已 `After=mysql.service`，新增单元用 `Before=` 表达顺序即可，
无需修改它们——少改一处就少一处出问题的可能。

**失败行为。** 连接失败时重试（指数退避，默认 30 次、上限 150 秒），
每次的 MySQL 错误号都进日志；彻底失败则退出码 3，systemd 按 `Restart=on-failure`
每 20 秒再试。业务服务**不依赖**它成功才启动（`Before=` 只决定顺序），
因此数据库彻底挂掉时页面仍然可用，只是留痕会如实提示不可用。

## 6. 排错速查

| 现象 | 看哪里 | 常见原因 |
|---|---|---|
| 服务 `failed` | `journalctl -u cf-db-connect -n 50` | 口令过期/被改；`.env` 被改成 644 导致程序拒绝读取 |
| 退出码 2 | 日志"配置载入失败" | `.env` 里缺 `CF_DB_PASSWORD` 等键 |
| 退出码 3 | 日志"已达最大尝试次数" | MySQL 未起或端口不对；确认 `CF_DB_PORT=3306` |
| 退出码 4 | 日志"已有实例正在执行" | 正常，非错误：并发时的互斥保护 |
| 缺表告警 | 日志"以下表不存在" | 用管理员跑一次 `sql/v8_schema.sql`，或 bootstrap 加 `--allow-ddl` |
| 日志文件一直是空的 | `ls -ld /var/log/cashflow` | 属主应为 cfrun；由 `LogsDirectory=` 自动保证 |

手工跑一次（带完整输出）：

```bash
runuser -u cfrun -- /opt/cashflow/venv/bin/python -B \
    /opt/cashflow/scripts/db_autoconnect.py \
    --env-file /opt/cashflow/deploy/.env --once
```

## 7. 桌面会话（本服务器无桌面，仅供参考）

若在带桌面的机器上使用，安装一个 XDG 自启动项即可：

```bash
mkdir -p ~/.config/autostart
install -m 0644 cf-db-connect.desktop ~/.config/autostart/cf-db-connect.desktop
```

`.desktop` 执行的是同一个程序，并带 `--once --fresh-secs 300`，
因此与 systemd、登录 shell 三者任意组合都不会重复连接。
