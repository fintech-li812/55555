## 二、冲突条目清单（15 项）

### A 类：阈值与符号不一致

| 编号 | 冲突项 | 位置 | 冲突点 |
|---|---|---|---|

### B 类：作用域冲突（条件是否独立生效）

| 编号 | 冲突项 | 位置 | 冲突点 |

| **C-3** | Q 阈值个数与语义 | §2-A.3：单一阈值，"进入第三层复核"；§2-A.7 与代码：0.3 / 0.5 两个阈值，且 `Q<0.3` 直接判红灯 | 阈值从 1 个变 2 个；语义从"转复核"（流程）变成"直接定级"（结论），**两处描述的是不同层面的事却被当成同一条规则引用** |

## 三、冲突在哪些输入下会失效 / 不确定 / 互相抵消

| 边界条件 | 触发的冲突 | 后果 |
|---|---|---|
| **P = 0.7000** | C-1 | 按 §2-A.3 是黄灯，按 §2-A.7 是红灯 —— **结果不确定** |
| **D ≥ 0 且 P ≥ 0.7** | C-2 | 第三层最强舞弊信号被完全丢弃，可对一个 P=0.98 的样本判"绿灯 · 不触发动作"。**规则互相抵消**：第三层在融合中等同死代码 |
| **Q < 0.3 且 D ≥ 0 且 P < 0.3** | C-3 | 数据质量差，但复核已排除粉饰、判别也健康，仍判红灯 —— **第一层强制红灯与第三层的排除结论直接冲突** |
| **Q ∈ [0.3, 0.5) 且 D ≥ 0** | C-4、C-6 | 无明文规则，结果由"按较严格者判定"这句未定义的话决定 —— **规则失效** |
| **Q < 0.3 且 D < 0 且 0.3 ≤ P < 0.7** | C-5 | 红灯与黄灯条件同时成立，结果取决于 `if/elif` 书写顺序。**调换顺序即从红灯变黄灯** |
| **Q = None / NaN / 1.5** | C-7、C-15 | `None` 崩溃；`NaN` 静默黄灯；**`Q=1.5`（明显非法）判绿灯** —— 数据质量得分非法时反而放行，方向性错误 |

## 四、统一术语与判定标准（消歧）

### 4.1 术语

| 术语 | 定义 | 取值域 |
|---|---|---|
| Q | 数据质量得分 = 1 − (ΣB + ΣM) / (2 × 指标数) | [0, 1] |
| D | 财务健康判别得分 = (Σv·投入 + Σu·产出) − 临界值 | 实数，`D < 0` 为风险 |
| P | 舞弊概率 = 随机森林多数投票 | [0, 1] |

### 4.2 状态离散化（区间一律**左闭右开**）

先把三个输入离散化为有序状态，规则只针对状态书写。这样"边界怎么算""两个阈值之间算什么"这两类歧义从根上消失。

| 维度 | 状态 | 判定式 |
|---|---|---|
| Q | 缺失 / 严重不足 / 存疑 / 达标 | 空值非数值越界 / `Q<0.3` / `0.3≤Q<0.5` / `Q≥0.5` |
| D | 缺失 / 风险 / 正常 | 空值非数值或**上游降级** / `D<0` / `D≥0` |
| P | 缺失 / 高 / 中 / 低 | 空值非数值越界或**树数=0** / `P≥0.7` / `0.3≤P<0.7` / `P<0.3` |

### 4.3 阈值的裁决

| 争议 | 裁决 | 理由 |
|---|---|---|
| `P > 0.7` 还是 `P ≥ 0.7` | **采用 `≥`** | §2-A.7 是规范公式、§4 规则表与代码均为 `≥`，三比一；§2-A.3 的 `>` 视为笔误 |
| `P ≥ 0.5` 还是 `P ≥ 0.7` | **采用 0.7** | 前端是唯一的 0.5，属于展示端抄录错误；后端与文档一致为 0.7 |
| P 是否可独立触发红灯 | **不可**，须与 D 联合 | §2-A.7 是规范公式；§2-A.3 流程图的上下文明确限定"对第二层判定为风险的样本做复核"。§4 规则表是摘要，表述不完整 |
| `Q<0.3` 是"转复核"还是"红灯" | **二者都成立，但分属不同层面** | §2-A.3 描述的是**流程**（低质量必复核）；§2-A.7 给出的是**结论**（质量严重不足即红灯）。文档已加注说明，不再互相引用 |

### 4.4 来源优先级：**Q > D > P**

数据不可信时，后两层建立在数据之上的结论失去基础。这是 §2-A.3 "前一层的输出是后一层的输入"的直接推论，不是新增约束——原代码里 `Q<0.3` 已经是短路条件，只是没有写成显式的优先级。

### 5.2 三条结构性质的证明

| 性质 | 如何保证 | 验证方式 |
|---|---|---|
| **互斥** | 每行是 (Q状态集, D状态集, P状态集) 的笛卡尔积，各行两两不相交 | 遍历 48 组合，断言每条**恰好**命中 1 条规则 |

## 六、异常与多源场景的处理逻辑

每种情况都有明确可判定的结果，**无一种落到"未定义"**：

| 场景 | 处理 | 结果 | 规则 |
|---|---|---|---|
| **Q = None** | 判不可用（不崩溃） | 红灯 + `Q可用=False` | R1 |
| **Q = NaN / ±Inf** | 判不可用 | 红灯 | R1 |
| **Q = "0.8"（字符串）** | **不隐式转换**，判不可用。Q/D/P 均由内部 `round()` 产出，出现字符串只可能是上游契约被破坏；`float("0.8")` 会把类型错误悄悄变成一次正常判定 | 红灯 | R1 |
| **Q = True（布尔）** | 判不可用（bool 是 int 子类，但作为质量得分出现必是缺陷） | 红灯 | R1 |
| **Q = 1.5 / -0.1（越界）** | 判不可用，**不裁剪到边界**（裁剪会伪造出"看起来合法"的输入） | 红灯 | R1 |
| **Q = 1.0000000004（浮点噪声）** | 容差 1e-9 内视为合法 | 正常判定 | — |
| **D = None / NaN** | 判不可用 | 黄灯 + `D可用=False` | R3 |
| **DEA-DA 求解降级** | 由调用方传 `d_reliable=False` | 黄灯 + `D可信=False` | R3 |
| **P = None / NaN / 越界** | 判不可用 | **不允许绿灯** | R9 |
| **随机森林树数 = 0** | 由调用方传 `p_reliable=False` | **不允许绿灯**（否则 P=0.0 会被当成"排除粉饰"） | R9 |
| **多源冲突：三层 vs 缓冲** | 取较严格者，但**只让已知灯色参与比较** | 见下 | — |
| **缓冲维度缺失** | 显式标注"未参与比较"，口径文案动态生成 | 最终等级仅由三层融合给出 | — |
| **来源优先级变化** | Q > D > P 固定：Q 不可用时短路，不再看 D/P | 红灯 | R1/R2 |
| **规则顺序变化** | 因互斥，结果不变 | — | 顺序无关性测试 |

### 6.1 取严逻辑的两处修复

```python
# 修复前：未知等级按默认 0（绿灯，最宽松）参与比较 —— 取严失效
if buffer_judge and rank.get(buffer_judge["等级"], 0) > rank.get(final_level, 0):

# 修复后：只有已知灯色才参与比较；口径文案按实际参与维度生成
if buffer_level in rank and rank[buffer_level] > rank.get(fused_level, 0):
```

| `Q = 1.5`（越界） | **绿灯** | 红灯 | R1 | ⚠️ **质量得分非法却放行，方向性错误** |

| `P = None` | **崩溃 TypeError** | 黄灯 | R9 | |

### 7.4 与 v2 legacy 的交叉校验

在合法输入网格（3×2×3=18 格）上，两套规则**仅 1 格不同**：

| q | d | vote | legacy_fuse | fusion.fuse | 规则 |
|---|---|---|---|---|---|
| 0.8 | 0.1 | 0.9 | 绿灯 | 黄灯 | R6 |

其余 17 格完全一致。该差异已由测试固定，两套规则不会静默漂移。

> 注：`legacy_fuse` 保留不删除——它标注为 "legacy screening; not fraud evidence"，是 v2 的向后对比基线。已在其 docstring 中注明**不是 v8 的权威口径**并指向 `v8/fusion.py`。

### 7.5 唯一的行为变化：FUSE-R6

这是本次消歧**唯一需要业务确认**的一格，也是唯一的实质行为变化：

- **修改前**：`D≥0 且 Q≥0.5` 无条件判绿灯，完全不看 P。
- **问题**：第三层输出在融合中被彻底丢弃。可以对舞弊概率 98% 的样本判"绿灯 · 仅记录，不触发动作"。
- **修改后**：`D≥0 且 P≥0.7` → 黄灯，依据"两个结论冲突，不放行绿灯，转人工复核"。
- **为什么是黄灯不是红灯**：红灯口径（2-A.7 规范公式）要求 `D<0 且 P≥0.7`，不因本次消歧而改动；红灯会触发"双签 + 24h 响应"，对"财务健康但数据可疑"过重。黄灯的动作是"@部门经理、48h 提交方案"，与该情形匹配。

**关于"不引入无关新约束"的说明**：R6 属于**消除内部矛盾**而非新增业务约束。它补上的正是原绿灯定义里缺失的一环——绿灯的语义是"证据一致支持健康"，而 `P≥0.7` 直接否证了这一前提。红灯与黄灯口径一字未改。
