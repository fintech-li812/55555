# ra-next-0.3 算法体系评审

评审对象：`algo/RA_NEXT`（VERSION=`ra-next-0.3`，2026-10-29）
评审人：工程侧（本助手）｜日期：2026-10-29
方法：不采信 ITERATION_03 自述，独立跑测试 + 自建探针复算关键量。所有数字可复现，脚本逻辑见本文附录。

---

## 一、一句话结论

**这是一次方法论水平很高、但信息产出极低的算法迭代。**

v0.3 在"证据诚实"上做到了同类项目少见的程度——每个数字都标注了它不意味着什么。但把三层精密机制串起来看，最终进入决策的只有 **D 的符号这一位**；而默认配置下（Q 未声明适用）这一位也被覆盖成红灯，**全部企业同色**。也就是说：**机制复杂度 ×48 格，信息量 ×1 bit，默认配置下 ×0 bit。**

这不是"实现有 bug"，是**体系设计与决策目标脱节**：整套算法没有定义"好"是什么（目标函数缺位），所以无法自我评价，也无法判断哪一层值得保留。

## 二、三条硬证据（全部为本轮实测，非引用其文档）

### 证据 1：Q 层是常数，融合表第一层永久失效

在 60 个独立生成的"干净"样本池上跑 `quality_gate`：

| 指标 | 实测值 |
|---|---|
| Q 取值分布 | 1.0 × 55 个、0.9667 × 4 个、0.9333 × 1 个 |
| 均值 | 0.9967 |
| 实际取值范围 | **[0.9333, 1.0000]** |

融合表的阈值是 `Q<0.3 → 红灯`、`Q≥0.5 → 达标`。**Q 的实际取值永远落在 0.93 以上，两个阈值都不可达。**第一层不是"通过"，是"不存在"。

再看检出力（用其自身 `_tamper` 注入粉饰）：

| 池中造假记录占比 | 0% | 10% | 20% | 30% | 50% | 100% |
|---|---|---|---|---|---|---|
| Q | 1.000 | 1.000 | 1.000 | 0.967 | 0.967 | **0.900** |

即使**整池 100% 换成它自己定义的风险样本**，Q 也只掉到 0.90（30 项里 3 项被拒）。原因在 Holm 校正 + 小样本：单指标 20 条记录全被篡改时，单项 p 只有 0.0025，而 30 项 Holm 的首位门槛是 0.05/30=0.00167——**差一点就是不拒绝**。

结论：Q 不具备"门禁"的判别力，它是一个恒等于 1 的常数。

### 证据 2：Q 算的不是这家企业

```
Q(healthy) = 0.9333
Q(edge)    = 0.9333
Q(risk)    = 0.9333
```

三个受评对象 Q 完全相同——因为 `quality_gate(pool)` 的入参是**训练池**，受评企业的数字根本没进这个函数。第一层名义上是"受评对象数据质量"，物理上不可能发现"这家企业报表造假"。

更根本的对象错位：Benford/末位均匀的适用对象是**自然跨量级的原始金额**（凭证、流水、科目发生额），而这里检验的是**派生比率**（0.156、2.10、9.80 这类有界比值）。比率天然不服从 Benford，末位也已被四则运算污染。**用一个先验就为假的原假设去做检验，结论没有解释力。**

### 证据 3：三层融合现实可达 5 条规则，默认配置 1 条

对 48 格决策表做穷举可达性分析（Q 限制在实测区间 [0.9,1.0]）：

| 规则 | 等级 | 可达状态数 |
|---|---|---|
| FUSE-R10 | 绿灯 | 48 |
| FUSE-R4 | 红灯 | 24 |
| FUSE-R5 | 黄灯 | 120 |
| FUSE-R6 | 黄灯 | 24 |
| FUSE-R9 | 黄灯 | 72 |

**48 格里实际只走得通 5 条。** 默认配置（`benford_applicable=False` → Q 缺失）更狠：

```
healthy → 红灯 (R1)   edge → 红灯 (R1)   risk → 红灯 (R1)
```

**100% 红灯。** 一个对所有企业都判红灯的系统，等于没有系统——它把"无法判断"和"高风险"混成了同一个输出，现场只会有两种反应：全部人工复核（成本爆炸）或集体忽略红灯（风控失效）。这两种都是失败模式。

## 三、逐层体检

### Q 层（数字分布检验）

- **做对的**：Holm 控制族错误率、MC 而非渐近 χ²、p 值加 1 避免零 p、明确声明 Wilson 区间只反映模拟误差。这些都是教科书级正确。
- **做错的**：检验对象错位（比率 vs 原始金额）、检出力不足（Holm × 小样本）、以及**把 Q 当连续分数接进阈值**。Q 的实际分布是 {0.93, 0.97, 1.00} 三个点，把它和 0.3/0.5 比较，是拿一个三值变量去做连续刻度的事。
- **v0.3 的处理方式**：不再修 Q，改为"默认不声明适用性 → Q 缺失 → R1 红灯"。这是**用关闭一层来回避一层的失效**，代价是全体红灯。

### D 层（DEA-DA + LP 最优性证书）

这一层是本轮**技术含量最高**的部分，也是我最愿意给正面评价的部分：

- 纯标准库两阶段 Bland 单纯形，第一阶段人工变量、第二阶段原目标，冗余行删除、奇异基/迭代上限/无界/不可行全部显式失败；
- 用弱对偶构造 `min bᵀy, Aᵀy≥c` 的对偶证书，核验原始残差、对偶违规、间隙，容差 1e-7，并**明确说这是数值证书不是有理数证明**；
- 30 个随机 LP 与 SciPy HiGHS 目标一致，实际 DEA 对偶间隙 4e-14。

工程实现上没有问题。**问题是它换来了什么。**

实测权重（edge 场景）：

| 指标 | 权重 | bootstrap 区间（30 次） |
|---|---|---|
| AR_DAYS | 0.414 | [+0.075, +0.575] |
| X6 | 0.262 | [0, +0.484] |
| X3 | 0.152 | [0, +0.291] |
| X7 | 0.080 | [0, +0.250] |
| X9 | 0.060 | [0, +0.170] |
| X1 | 0.032 | [0, +0.227] |
| X2 | 0.000 | [0, +0.371] |
| X13 | 0.000 | [0, +0.371] |

**8 个权重，8 个区间都含 0。** 没有任何一个指标的权重在统计上可与 0 区分。这不是"某个指标不重要"，是**权重向量不可识别**——LP 在归一化约束 `Σv+Σu=1` 下存在多重最优，返回的只是其中一个顶点。把 AR_DAYS=0.414 解释成"应收周转最重要"，没有证据支撑。

再看 D 的稳定性：

```
healthy  D= 0.8685  区间 [ 0.478,  0.937]
edge     D= 0.1877  区间 [-0.090,  0.305]   ← 跨 0
risk     D=-0.4711  区间 [-0.961, -0.434]
```

而融合表**只用 D 的符号**（D<0 / D≥0），量级完全丢弃。所以：

> 本层用 30 次 bootstrap + 独立单纯形 + 对偶证书 + 跨平台校验建立的全部精度，最终只影响一个 bit；而这个 bit 在 edge 场景的 bootstrap 区间里正好跨 0。

同时 D **没有任何样本外泛化证据**：没有 LOO、没有分层 K 折、没有 AUC/KS。有 OOB Brier 的是 P，而 P 恰恰是最没被使用的那层。**该验的没验，验了的没用。**

### P 层（随机子空间森林 + sigmoid 校准）

- 承认得很到位：OOB Brier ≠ 校准后 Brier、calibration_reliable ≠ 概率真实、随机子空间 ≠ 逐节点随机森林、类别不重平衡保留自然频率。这些区分是对的。
- **但 `calibration_reliable` 的门槛（校准集 ≥30）在默认池下永不满足**：

| 每组样本数 | 池总量 | 校准集 | reliable |
|---|---|---|---|
| 20（默认） | 40 | 10 | False |
| 40 | 80 | 20 | False |
| **60** | **120** | **30** | **True** |

也就是说，**P 要参与决策，样本池必须扩到 120 例**；默认 40 例时 P 一律被丢弃。三层里的第三层，在默认配置下是死代码。

- 种子敏感性实测（同池同目标，8 个种子）：P ∈ [0.768, 0.914]，**跨度 0.146**。跨阈值 0.7 的余量只有 0.068。**单一种子可复现，不等于结果稳健**——换个种子就可能翻色，这正是"看起来确定、实际不稳"的典型。没有做多种子平均。

### 动态阈值政策

设计上有两个点是对的，值得保留：

1. **静态下限** `max(静态阈值, 分位数)`——防止企业持续低缓冲后，"越差越宽松"的自我归一化。这是真问题，解法也对。
2. **严格月份连续性 + 拒绝未来月**——防前瞻偏差，且"不静默丢行"符合审计要求。

弱点：12 个点估 P10，等于用第 1–2 个次序统计量定红线，方差极大；3 个月循环块 bootstrap 在 12 个点上块结构几乎退化为整体重采样，区间不可信（他们自己也写了"不保证覆盖"）。且这是**水平阈值**，没有季节性、没有趋势、没有回款周期，与 13 周现金流预测模块完全脱节。

### 统一视图

`取最严重等级 + 缺一维不得绿灯 + 全缺失待复核`——这条政策方向正确，且明确说"不是联合概率"，没有伪造精度。**唯一的问题是它与融合层自相矛盾**（见下）。

## 四、体系级缺陷（比单点 bug 重要）

### 缺陷 1：语义不一致——缺证据，一处升灯一处降灯

- `unified_view`：缺证据 → 绿灯**升**为黄灯（证据不足不得放行）。
- `fuse`：`p_reliable=False` → **R5 红灯降为 R9 黄灯**。

同一个原则（证据缺失），在两个模块里推向了相反方向。后果是具体的：

```
risk 场景  D=-0.4711（明确为负）、P=0.9666（最高档）
  v0.1/工程适配层：红灯（R5，D<0 且 P≥0.7）
  v0.3 默认语义  ：黄灯（R9，P 证据不可用）
```

**最危险的样本从红灯降成黄灯。** ITERATION_03 诚实地写了"这不表示风险降低"，但诚实不能替代正确：正确的处理是把"证据不足"映射到**人工复核队列**（第四个状态），而不是映射到**较低严重度**。缺证据应当增加不确定性，不应减少严重度。

### 缺陷 2：没有目标函数，所以无法判断哪层该留

整套体系没有回答：输出是用来做什么的？

- 若用于**审批排序** → 需要 AUC/KS、审批率-坏账率曲线、成本矩阵；
- 若用于**单户预警** → 需要召回率、提前期、误报成本；
- 若用于**监管报送** → 需要可解释性和稳定的规则文本。

现在三者都不是：输出是一个颜色，颜色没有对应的动作、成本或责任。**没有目标函数，就无法回答"Q 该不该保留""P 的 0.7 该定在哪"**——这也是为什么三轮迭代都在打磨"证据质量"，而没有一轮在打磨"决策质量"。

### 缺陷 3：验证是循环的

合成数据生成器 `_base_values` 明确写着：健康组"按 Benford 概率生成首位数字"，风险组"额外施加粉饰痕迹"。也就是说：

> 数据的生成假设 = 算法的检验假设。

D 能把两组分开（0.87 / -0.47）、P 能给出 0.03 / 0.97、Q 能检出 3 项——**这些都是生成器的性质，不是模型的性质**。合成数据可以证明"代码跑得通"，不能证明"方法有判别力"。这一点文档里承认了（"没有真实企业准确率"），但承认之后三轮仍在同一套合成数据上加机制，边际信息量为零。

### 缺陷 4：缺失值的处理是"全有或全无"

`valid_values` 要求 15 个比率**全部存在且有限**，缺一个 → 整条链不可用 → 红灯。真实财报必然有缺项（无应收、无存货、无研发）。**一个缺项就判红灯的系统，在真实数据上红灯率会是 100%**，与缺陷 1 叠加后，可运维性为零。

### 缺陷 5：工程上不可集成（我作为接入方必须指出）

实测：

```
$ python -c "import algo.RA_NEXT.reference as r; r.deada(pool, tgt)"
ModuleNotFoundError: No module named 'certified_lp'
```

- `reference.py` 内部 `from certified_lp import solve` 是隐式同目录导入，**只有在 `algo/RA_NEXT` 作为 cwd 时才能工作**，不是可安装的包。
- `diagnosed_deada` 用 `exec(compile(inspect.getsource(baseline.deada)))` 把基线函数源码重编译进一个打了补丁的命名空间。基线函数一旦改签名、改闭包引用、或被打包成 pyc-only，就会**静默取到错误结果而不报错**。这是维护地雷。
- 所有模型每次请求重算，无持久化、无批处理、无并行；40 例池单场景 0.26s，1 万户批量约 43 分钟。

这也是我上一轮没有直接 import、而是重写成 `v8/ra_next.py` 的原因——生产不能依赖研究目录的目录结构。

## 五、值得肯定的部分（不打折扣）

1. **认识论纪律**：`available`（数值可算）与 `calibration_reliable`（可作决策依据）分离；MC 区间声明"不是企业真实性区间"；数值证书声明"不是精确证明"；OOB Brier 声明"不是独立校准性能"。这种自我限定在算法项目里极少见，是真实资产。
2. **LP 证书是硬功夫**：独立实现 + 对偶构造 + 冗余行处理 + 显式失败路径 + 与 HiGHS 对照。即使当前只影响一个符号，这段代码本身可以独立复用。
3. **负面结果不删**：保序回归失败的 `experiment_isotonic_rejected.json` 保留在目录里。这比任何"我们效果很好"的结论都有价值。
4. **动态阈值的静态下限**：防止"越差越宽松"，这是真正的业务洞察，不是技术炫技。
5. **边界自律**：明确不接生产、不改 48 格、不擅自改业务口径、把待裁决项留给业务。这是对的。

## 六、给第四轮的方向（按性价比排序）

| 优先级 | 动作 | 理由 | 验收 |
|---|---|---|---|
| P0 | **先定义决策目标**：输出是 PD 排序、审批建议、还是预警工单？定成本矩阵 | 没有目标函数，后续所有调参都无判据 | 一页纸写清"输出→动作→成本" |
| P0 | **Q 退出融合，降级为数据质量报告** | 实测为常数，留在融合里只制造"三层"的错觉 | 融合表由 48 格减到 2×2×2，且每格可达 |
| P0 | **修"缺证据降灯"**：把 `p_reliable=False` 映射到"待复核"，不得降低严重度 | 最危险样本从红降黄，是方向性错误 | risk 场景灯色 ≥ 黄且必须带复核标记 |
| P1 | **D 加样本外验证**（LOO 或分层 5 折，报 AUC/KS）+ 权重唯一化（NNLS 或 L1-LP） | 权重 8/8 区间含 0，不可解释；无泛化证据 | 权重区间不含 0 或明确标注"不可识别" |
| P1 | **P 多种子平均 + 模型持久化**；主指标改 PR-AUC/KS | 单种子跨度 0.146，跨阈值余量仅 0.068 | 8 种子方差 < 0.03 |
| P2 | 数字分析改到**原始金额层**，或直接删掉 | 对派生比率做 Benford 先验为假 | 有/无该层对 AUC 的增量 ≥ 0 |
| P2 | 缺失值分级降级（缺 1–2 项 → 降权 + 标记；缺 ≥5 项 → 不可用） | 全有或全无在真实数据上不可运维 | 缺 2 项时仍能出结论并带标记 |
| P2 | 时序特征接入（13 周预测、趋势、波动率） | 现在与主链完全脱节 | 融合输入含时序维度 |

## 七、对工程接入的判断（我方立场）

1. **v0.3 不作为默认算法接入**。默认全员红灯，接入等于把线上判成"全风险"。
2. **v0.3 的 `p_reliable = calibration_reliable` 语义不采纳**。现行工程适配层 `v8/ra_next.py` 仍用 `树数>0`，因此 risk 场景仍判红灯。若采纳 v0.3 语义，最危险样本会降为黄灯——这一条需要业务书面确认，不能由算法侧单方面改变。
3. **可立即吸收的两项**：`certified_lp` 的对偶证书（作为离线回归工具，不参与线上路径）、`decision_policy.threshold_policy` 的静态下限与月份连续性校验（作为独立策略模块，不并入融合）。
4. **建议把"证据完整度"做成独立维度**，与三色并列输出（完整度：高/中/低/不可用），而不是把证据缺失压进颜色里。
