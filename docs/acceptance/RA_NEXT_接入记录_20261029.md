**复核确认的三处算法改动**（与 `ALGORITHM.md` 自述一致）：

1. **Q**：χ² 临界值 → 多项分布 Monte Carlo 精确 p 值（1999 次）+ 30 项检验 Holm 校正，`Q = 1 − 拒绝数/30`。
2. **D**：算法未变（Bland 单纯形、点估计与基线逐位相同），仅把求解失败时的 D 置 None，另加 30 次分层 bootstrap 稳定性区间。
3. **P**：训练池风险数字 → 固定首位数字自信息（解耦）；全特征森林 → 每树抽 5/30 维；新增 OOB、独立分层校准集（每类 1/4，最少 3 例）、正则 sigmoid 校准。

## 二、接入方式（双版本并存）

### 2.1 新增生产适配层 `mcp-server/program_v1/src/v8/ra_next.py`

**不直接引用 `algo/` 目录**——研究目录将来可能被清理，生产不能依赖它。适配层自己实现，数值与候选逐位一致（已验证），并补三件生产必需的事：

| 补齐项 | 说明 |
|---|---|
| 不可用显式化 | 一律 `available=False` + `reason`，`Q/D/P` 键始终存在（值为 None），调用方不会 KeyError |
| 输入防御 | 布尔/字符串/NaN/Inf/缺键/类别不足 → 判不可用，不抛异常到 HTTP 层 |
| 确定性 | 全部随机过程固定 seed，返回值不含耗时等非确定字段（可直接逐位比对） |

### 2.2 编排层 `v8/engine.py`

```python
engine.assess(industry, scenario, amount, n_per_group, algo="v8", with_stability=False)
```

- `algo="v8"`（默认）：基线三层模型，行为与接入前完全一致。
- `algo="ra-next-0.1"`：走 RA_NEXT。
- 两版共用同一张融合决策表（`fuse-v2.0`，48 格未改）。
- `with_stability=True`：额外跑 30 次分层 bootstrap（约 1~2 秒，默认关闭）。
- 输出新增 `算法版本` / `稳定性` / `声明.算法口径` 三个字段，其余 schema 不变。

### 2.3 服务层 `v8_server.py`

| 接口 | 新增参数 | 说明 |
|---|---|---|
| `GET /api/v8/assess` | `algo`、`stability` | 例：`?scenario=edge&algo=ra-next-0.1&stability=1` |
| `POST /api/v8/save` | `algo` | 留痕按所选算法复算后落库 |

### 2.4 前端 `web/统一工作台.html`

配置面板新增「算法版本」下拉（v8 基线 / ra-next-0.1），运行与保存均带该参数；结果区显示算法版本，新版 Q 全过时追加橙色阈值提示。

## 四、未解决项（需算法侧/业务侧处理，工程侧不擅自改）

| # | 问题 | 证据 | 处理建议 |
