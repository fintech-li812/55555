# 答辩记录：这套 Workbench 到底是不是"以千问办公为核心"

日期：2026-10-27。形式：模拟评委质疑，逐条回答并给出判定。
答辩方：WorkBuddy（本项目策划与实施）。
性质：**内部压力测试记录**。目的是提前把能站住的和站不住的分开，避免把未达标项包装成已达成。

---

## 0. 答辩规则

- 站得住的讲证据，站不住的直接认输并写进第 4 节"未达标清单"。
- 不用"SHOULD 可以""理论上支持"这类含糊表述蒙混；没跑出来的就说没跑出来。
- 每条判定必须**可证伪**：给出若为假时会观察到什么。

**我方主张**：整套系统的运行位置、数据归属、生命周期、运维责任四项全部落在千问办公账号下，对外只有一个 `*.qwenwork.host` 网址，开发者本机不参与任何生产链路。

---

## 1. 逐条答辩（一）：核心性质与技术路线

> 本组含 Q1–Q5，各自的独立判定写在每题末尾，总体上偏向"站得住"，但 Q1 只是有条件成立。

### Q1｜你的计算内核是 Node 代码，千问只是个托管商。搬到 Vercel、阿里云照样跑，凭什么叫"以千问为核心"？

**答**：区分两件事。

**技术可迁移性**上，我认——这套代码没有任何一行绑定千问私有 API，理论上可迁移。这一点我不狡辩。

**运行事实**上，它在四个层面确实长在千问里：

1. **生命周期绑定**：网页、域名、数据库是一体的，删网页等于清空数据库。这个耦合是平台级的，不是我们写出来的配置。
2. **运维责任**：服务器、证书、CDN、扩容、冷启动全部由千问承担，我方没有第二台机器、没有第二个进程需要值守。
3. **身份与生态**：用户现有的技能包、9 个 MCP 工具、桌面端闭环都在同一千问账号体系下；这不是巧合，是用户刻意的选择。
4. **对外形态**：唯一入口是 `.qwenwork.host`，没有旁路。

一个类比：跑在 Salesforce 上的业务应用，代码是 Apex/Java，没人因此说它不是 Salesforce 应用。

**判定：有条件成立。** 是"事实与产品定位层面"成立，不是"技术锁定层面"成立。
**若为假会怎样**：如果我们需要在千问之外单独维护一台服务器，或访客需要访问第二个域名，"以千问为核心"立即不成立。

---

### Q2｜你说"云端不解析上传件，只读固化 fixture"——这不就是把结果写死吗？四个来源的输入写死，页面上那 185000/77000/177000 还有什么可信度？

**这是全场最关键的一问，也是最容易被糊弄过去的一问。**

**答**：把**输入**固化和把**输出**写死，是两件完全不同的事。

- 被 SHA256 绑定的是**输入**：哪一个工作簿、哪一张表、哪一行、什么单位。这些本来就该是固定的测试输入，交接文档第 6 节明确写着"两份期初/期末证据是分别显式构造的测试输入，不由运行时计算结果回填"。
- 页面上的每一个金额，必须**由内核从这些输入算出来**。审判性判据只有一个：**可证伪性**。

**所以我主动追加一条验收（第 9 条）**：

> 从 fixture 里删掉或修改任意一笔银行流水，页面上的三类汇总必须相应变化，并且独立余额核对必须报出非零差异。若改动输入而结果纹丝不动，即判定为写死，本次交付不予通过。

**判定：站得住**，且我把判据升级成了可执行的验收项。
**若为假会怎样**：改输入而输出不变 → 立刻证明是展示页而非计算系统。

---

### Q3｜AI 到底通不通？你架构图上那个"AI 适配器"，是不是在画饼？

**答**：目前**没通**。千问能不能在动态网页内调用模型、要不要自配 Key、额度怎么算，探针还没回。

我的处理是**不做假聊天框**：

- 探针给出可用路径 → 接，且模型只有工具白名单，永远拿不到算钱的权力；
- 探针答不出来 → **不上 AI 对话框**。宁可交付一个"没有 AI 但每个数字都真实"的工作台。

**判定：诚实性站得住，功能上缺失。**
**若为假会怎样**：若页面上出现一个能聊天的框，但背后没有真实编排，那就是欺骗，比没有 AI 严重得多。

---

### Q4｜本地 D 盘 Python 还在参与，你这算哪门子"云端独立"？

**答**：它已经退居为一个**离线裁判**，不在生产链路上。

- 生产请求从浏览器出发，到千问 Node 结束，中间不碰 D 盘任何一个字节。
- 它的唯一职责：为每个移植模块提供基准值，做逐字段对拍。
- **自证方式**：Stage 5 第 7 项验收要求——开发者电脑关机，另一台设备仍能完整跑通计算与回查。这个测试一旦通过，D 盘参与与否的问题自动消失。

**判定：站得住**，靠关机测试自证。
**若为假会怎样**：关机后另有设备跑不通 → 说明仍有隐藏的本机依赖，需如实报出。

---

### Q5｜Python 版和 Node 版两套代码并存，哪套算准？会不会各说各话？

**答**：承认这是真实风险，解法是硬规矩：

1. 移植期间 **Python 一行不改**，它是唯一裁判；
2. Node 结果与 Python 不一致时，**永远先判定 Node 有错**，直到查清根因；
3. 任何时刻只允许存在一个真理源，不允许"两个都对"的说法；
4. 双跑对拍结果必须留痕，成为每次改动的回归网。

**判定：站得住，但必须写成硬规矩而不是默契。**
**若为假会怎样**：若某次不一致被判为"两边都有理"而放过，整个审计追踪链就断了。

## 2. 逐条答辩（二）：资源依赖

> 本组 Q6 的成立与否取决于探针结果，因此在探针回执到达前，不应把它写进任何对外承诺。

### Q6｜数据库挂不上怎么办？你整套"记录与留痕"是不是就塌了？

**答**：三条退路，且**全部提前声明**，不事后找补：

| 情况 | 行为 | 页面表述 |
|---|---|---|
| 能挂库 | 完整持久化 | "已保存，回执号 xxx" |
| 不能挂库 | 仅会话内回查 | "本次会话有效，**未持久化**" |
| 完全不可用 | 退还为概念验证 | 不提供保存功能，**不说成已保存** |

**核心底线**：**绝不谎称保存成功**。没有存储就说没有存储。

**判定：有条件成立**，取决于探针 Q3 结果。
**若为假会怎样**：若页面显示"保存成功"但其实没写库，属于欺骗性验收，一票否决。

## 3. 逐条答辩（三）：我方认输

> 以下三条没有辩解余地。它们不是"待优化项"，是**当前确实不成立**。

### Q7｜你连一个自己的域名都没有，谈什么"我们的 Workbench"？

**答**：**认输。** 这一项目前确实不成立。

事实是：

- 千问分配的 `*.qwenwork.host` 默认域名只能证明"跑在千问上"，不能证明"属于我们"；
- 要对外宣称自有品牌站点，需要：付费套餐 + 自定义域名 + ICP 备案 + 公安联网备案，备案主体与合规责任由用户自行承担；
- 这一项目前**一件都没做**，也不在当前 Stage 0-5 计划内。

**在做好之前，正确表述只能是"我方的千问办公工作台"，不能说"自主品牌站点"。**

**追加建议**：把它列为 Stage 6，而不是假装它不存在。

---

### Q8｜访客隔离只靠 cookie，这不是多用户系统，就是个玩具吧？

**答**：**认输。** 它就是演示级隔离。

- 没有登录、没有组织、没有角色、没有权限模型；
- 换个浏览器就是新身份，清除 cookie 就是失忆；
- 文档里我写的措辞一直是"访客"而不是"用户账户"，这个措辞差异是有意为之。

**但这是范围裁剪，不是缺陷隐瞒**：真实企业阶段必须引入真实身份体系，届时会话隔离这段代码要**整体重写**，不是改造。

**判定：认输，且明确它不是企业级能力。**

---

### Q9｜AI 功能现在是不是就是没有？

**答**：**是，就是没有。** 见 Q3。功能上目前不可辩护，能辩护的只是我们选择不造假。

## 5. 结论：这个命题在什么条件下为真

**"以千问办公为核心"这一命题，在同时满足以下三个条件时为真：**

1. 唯一的对外入口是 `.qwenwork.host`，没有第二个域名或第二个后端地址；
2. 开发者本机完全关机后，任一设备仍能完整跑通计算与回查；
3. 算法、数据、留痕三者的生命周期全部由千问账号持有，我方不另行维护任何生产进程。

**三条中任何一条不成立，就必须改口**——届时正确说法是"这是一个部署在千问办公上的普通 Web 应用"，而不是"以千问办公为核心的工作台"。

**第 1、2 条在正式验收时可当场验证；第 3 条不属于技术问题，属于你是否愿意继续投入的运营选择。**
