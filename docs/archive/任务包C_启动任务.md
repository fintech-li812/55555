# 包C 启动任务包 · 5 个当前可跑的小任务（按建议执行顺序）

> 挑选原则：不依赖 T0-1/2/3 裁决（口径留空位待填）、不依赖 MCP/数据库、产出即交付物、单人独立可完成。
> 参考材料都在 `docs/`：v8_完整方案.md（§7.1 对话分支、§4.3 报告模板、§7.2 问卷）、包B任务书（基准企业）、演示看板核对与改造清单。
> 通用红线：所有文案**不得出现量化承诺**（"提升 X%""准确率 X"），未实测的能力写"待验证"或走降级口径。

---

## C1 · 异常提醒推送文案（半天，最先做——钉钉连通器一挂就能用）

为 6 类事件各写一条钉钉推送模板 + 一条降级版（建群/@ 不可用时发普通群的版本）：

| 事件 | 触发 | @谁 | 时限要求 |
|---|---|---|---|
| 黄灯预警 | 缓冲倍数跌破 K黄 | 部门经理 | 48h 提交方案 |
| 红灯预警 | 跌破 K红 | 财务总监 + 总经理 | 24h 响应 |
| 压力测试红灯 | 联合冲击缓冲为负 | 管理层群全体 | 附健康度报告摘要 |
| 到账验证失败 | 金额不符/连续 2 次失败 | 责任人 | 重新提交 |
| 例外率异常 | 部门例外率>20% | 审计/内控 | 季度回溯报告 |
| 每日巡检简报 | 每日 9:00 | 测试群 | 绿灯也要发，一句话版 |

每条模板含：标题（≤20字）、正文（含哪些数字占位符如 `{缓冲倍数}`、`{K黄}`——**数字一律用占位符，不许写死**）、@列表、超时升级话术。
**完成标准**：12 条文案（6×2 版），每条占位符与看板字段一一对应，注明来源字段。

## C2 · Agent 追问话术模板（1 天）

v8 §7.1 的 8 条对话分支，各写一版回复模板：为什么是黄灯 / 凭什么判我红灯 / 主要原因是什么 / 最坏情况会怎样 / 数据有没有被粉饰 / 我们缓冲在行业什么水平 / 哪个部门例外最多 / 以后怎么避免。
每条包含：回复结构（先结论→再数字→再建议）、引用哪些数据字段（用占位符）、**超纲时的"我不知道"兜底话术**（v8 §9.2 专门有这项）。
**注意**：涉及融合判定的两问（黄灯/红灯），原因解释处留 `〔待 T0-1 裁决后填〕` 空位，其余照写。
**完成标准**：8 条模板 + 兜底 1 条，空位集中标注，不虚构判定逻辑。

## C3 · 演示脚本第一稿（1 天，`docs/演示脚本.md` 还是空占位）

以演示看板为界面，写答辩 10 分钟演示流程：每一步「点什么 → 屏幕出什么 → 口头说什么 → 这一步防哪个评委追问」。建议主线：四行业参数自适应（切换企业）→ 数据闸拦埋错（点名 X-MANU-05 单位混用，**只讲这一处**，别让 28 处部分到账刷屏）→ 缓冲倍数与灯 → 三层模型开关关掉回退 v7（合规落点）→ 压力测试联合冲击 → 例外回溯 → 审计留痕。
**完成标准**：脚本含每步时长分配、口头逐字稿、备选支线（如果评委打断问什么就跳到哪页）；引用数字全部来自看板实测可见值。

## C4 · 两份报告展示模板（1 天）

把 v8 §4.3 的健康度报告示例改造成正式 Markdown 模板，另新写《例外审批回溯报告》模板（v8 §4.2 只有统计规则没给报告样式）。两份都做成占位符版（`{企业名}`、`{例外率}`…），供定时任务/Agent 直接填充。
**完成标准**：两份模板各含"重点关注"与"建议措施（短/中/长期）"结构；例外报告含异常部门标记规则说明（>20%、连续 3 次同理由、金额>预算 15% 三条并列）。

## C5 · 科技服务业第 5 家企业样板的数据包（半天，做完丢给我）

看板缺科技服务业企业。你出「企业画像 + 数据草案」：企业名、12 个月经营性流入/流出序列（做出一次黄灯波动，参考现有零售样板的节奏）、M≈40、缓冲 B 取 50~60（落在黄灯区）、2~3 条备注。参数我来按 v8 §5.4 填，代码我来加。
**完成标准**：数据序列手加一遍合理（月度环比无跳变），B/M 倍数落在 1.0~1.5 之间。
