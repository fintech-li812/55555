我们不是做不到外接，我们是不确定接了以后还算不算"千问的"。

这句是全部问题的根，原样带到现场。

一、现场问题清单

30 秒自我介绍 · 可直接念 我们在做一个制造业现金流的分析工作台。

简单说：企业拿八张 Excel 表给我们——银行流水、应收账款、借款、投资这些——系统把每一笔钱分门别类归到"做生意的钱""买设备的钱""借来还去的钱"三类里，各自加总，最后拿算出来的期末余额去跟银行给的期末余额对账，差一块钱都要查清楚。

这套算法我们已经用 Python 写好了，在自己电脑上跑通了，四个测试场景全部对得上，负例会自动拒绝存档。

现在想把它做成一个网址、谁都能打开、我关机它也还在的东西。我们明确希望它是"千问办公的工作台"，而不是"随便部署在哪个云服务器上的一个网站"。

所以我今天想问清楚的就一件事：到底什么情况下，你们认为一个东西算"以千问办公为核心"？这条线画在哪？

我们现在自己下的四条定义

场所
整套东西跑在千问分配的一个 .qwenwork.host 网址里，没有第二个地址
钱在这算
金额由网址背后的程序算，网页本身一个数都不参与
数据在这存
用千问给网页配的数据库
生死在这
删掉这个网页，整套系统和数据一起消失

实测环境：Node v22、2 核 CPU、约 1 GB 内存、可联网、第三方包可打包进去。

卡住的地方：我们实测发现那条"往外走"的路是通的——完全可以把最值钱的计算搬到自己的服务器。所以"以千问为核心"对我们不是能力问题，是定义问题。这就是必须来问的原因。

必问 6 个 (回答不了，其余 15 个都白搭)

必问 A1｜你们有没有官方的判定标准？
「以千问办公为核心」，平台侧有没有一个可以对照的定义？是靠"跑在 Pages 上"就算，还是要看用了多少平台能力（网页、数据库、任务、工作流、身份）？
我想要一把可以打分的尺子，而不是我们自己给自己打分。
必问 A2｜我用自己的 Key 去调外面的模型，还算不算？
平台自己不提供模型调用能力（我们实测确认了）。那如果我在自己的程序里去接通义或者其他模型的 API——大脑在外面，身体在千问里——这还算"以千问办公为核心"吗？
必问 A3｜把钱放到别的服务器上算，算不算？
如果把最核心的金额计算放在自己的另一台服务器上，千问这边只负责展示页面——用你们的话说，这该叫"千问应用"，还是"套了个千问壳子的外部系统"？
这是我们上一版方案被自己人否掉的原因，我需要权威说法。
必问 A4｜反过来问：真正的编排在千问的"任务/工作流/智能体"里，网页只露一张脸——这种是不是反而更"核心"？
我们拿不准"核心"该押在网页上，还是押在千问的任务与智能体编排能力上。可能我们从一开始就押错了地方。
追问必杀技见下一节 →
必问 B1｜能不能注入自定义环境变量？
实测运行时只有 9 个平台自己的变量。我能不能自定义一个，比如塞一把 API Key 进去让服务端读到？
这一条直接决定我们的 AI 功能是生还是死。答"不能"，我们就干脆不做 AI。
必问 B3｜能往外发 HTTPS 请求，这是被允许的正常用法吗？
调到了 npm 的库和阿里云官网，都通。但不知道这是"支持的能力"还是"没人管的缝隙"。会不会有白名单、审计，或者以后被关掉？

二、A4 详解：押网页 还是 押编排

押网页 = 我在千问的商场里租了间铺面，自己当老板。铺子里的机器是我造的，账是这台机器算的。客人推开那扇门就进来了，他甚至不需要知道千问是什么。千问是房东兼物业。

押编排 = 我不开店了，改行当千问手底下的手艺人。用户不来我的门面，他直接跟千问说"帮我把这个月的现金流跑一遍"。是千问在听、在想、在安排先做哪一步，最后喊我们的手艺去干活。用户记住的是"我能让千问帮我做事"。

一句话区别：一个是"我的东西放在千问那儿"，另一个是"我长在千问身上"。

九个维度对比

维度押网页（现在方案）押编排
用户怎么接触打开一个网址跟千问说一句话
谁能用任何人，不需千问账号只有千问用户
对外名片一个链接可直接发给客户说不清，只能说"在千问里找我"
谁在算钱我们的 Node 代码，确定性取决于实现（见下，生死线）
数据存哪千问内置库，结构化未知：文档/表格/网盘/技能状态
搬得走吗搬得走搬不走
速度秒级，30 秒上限绰绰有余多一步调度，慢，烧 token
成本只有可能的套餐费每次运行都烧 token
"以千问为核心"成色弱（千问只是托管商）强（删账号即全灭）

第 9 行是核心。"以千问办公为核心"最怕的质疑是：搬去别家也能跑，凭什么叫以千问为核心？

押网页对这一问只能认输（事实如此）。而押编排是唯一能把这一问翻案的路——搬不走的才配叫核心。

生死线：A4 不是一道题，是四道

情形甲（工头派活）：编排只负责排顺序、传文件、调工具，真正算钱还是我们那套死代码 → 成立，而且很漂亮。

情形乙（AI 自己算）：由大模型现场读表、现场加总 → 对我们直接出局。

理由：我们做的是对账，差一分钱整份报告作废，而 LLM 天生是"大概率对"。金额绝不能交给概率。

编号要问的事为什么致命
A4a编排里"算"这一步，是 AI 自己在算，还是它去调一个外部工具？决定情形甲/乙，直接决定生死
A4b编排能不能调用我们自己写的确定性代码？技能、MCP 还是 HTTP？决定那 1644 行移植成果能不能复用
A4c结果存到哪？能进结构化数据库吗，还是只能落到文档/表格/网盘？决定"留痕+可回查+可导出"还能不能成立
A4d编排做出来的东西，有没有可以发给别人的公开 URL？决定我们还有没有对外交付物
A4 现场问法 · 可直接念 我们在做一个制造业现金流工作台，核心是一套已经验证过、能用 100 项回归测试的精密计算逻辑。

我们现在有两种做法，想请你们判断哪一种才算"以千问办公为核心"：
第一种是做一个动态网页，把计算逻辑整个搬进网页的 Node 后端，对外一个网址；
第二种是不做网页，让用户在对话里说一句话，由千问的任务编排去调度我们的计算。

我想问——
（1） 你说的编排，是让模型自己算数，还是它去调一个确定性的工具？我们的金额差一分钱就算废，不能交给概率。
（2） 编排能调用我们自己写的代码吗？以什么形态接进来？
（3） 编排跑完的结果能进数据库吗？还是只能落到文档里？
（4） 哪种才算你们认可的"以千问办公为核心"？

第（1）问最重要，也最容易得到含糊答案。
如果对方说"模型会调用工具"，必须追一句：

「那工具是我们的代码，还是你们平台的通用能力？」

答"通用能力" = 情形乙 = 我们出局。

推荐形态：一颗心脏，两个入口

千问账号 ┌──────────────────────────┐ │ 对外：网页网址 对内：对话编排 │ │ （任何访客） （千问用户） │ │ ↓ 共用 ↓ │ │ Node 计算内核（确定性） │ │ ↓ │ │ 同一个存储 │ └──────────────────────────┘

三条不可让步：

  • 心脏必须是确定性代码——不管从哪扇门进来，算钱的都是同一份 Node 内核，整数分运算，绝不让 AI 做加法。
  • 对外那扇门要保住——发给客户一个链接就能看，这是唯一拿得出手的交付形态。
  • 对内那扇门是加分项，不是救命稻草——它决定"以千问为核心"这句话的成色，不影响系统能不能用。

答案出来后怎么走

问到的答案我们怎么做已投入资产
"押网页"右门暂时封着，主线不变不作废
"押编排 + 工头派活"心脏不动，右门从"以后再说"提到"先做"不作废
"押编排 + AI 自己算"拒绝这条建议，并说明为何不能用概率算账不作废
"编排调不了你们的代码"右门降级为只做展示，心脏仍留在网页里不作废
对方也说不清按"押网页 + 右门暂缓"，A4 标记未决不作废
A4 的任何答案都不会推翻这半天的工作。唯一会让架构真重画的情况，是"必须用平台通用能力替代我们的计算逻辑"——那已经不是选择题，是产品性质变了。

三、路线规划：红线下的唯一解

推导方式：不是挑最好的，是把不可能的都划掉，剩下的就是答案。

红线清单（官方 2 条 + 我方 4 条）：不得把 secrets 打进发布包（.env 被硬拦，改名混包属违规）／不得含符号链接／金额只有一个出处且必须住在千问里／四个来源严禁混用，负例禁存／不写死结果，不谎称保存成功，不做没有后端支撑的假 AI／不对外公开真实企业数据。

四个岔路口，每个只剩一条活路

决策点划掉的选项为什么死幸存
AI 怎么接前端持 Key／配置混进包共享 Key 等于公开泄露／违反官方明文红线第一版不做
数据存哪自建外部库／免费不挂库存储一走，"核心在千问"立刻破功／可活但功能残缺千问内置库
钱在哪算浏览器里算／阿里云 Python访客能改，等于把算法交出去／钱在千问外面Node 内生
数据怎么保不做导出／临时目录落盘删网页 = 永久清库／容器销毁即丢专用导出端点

计算搬进千问的 Node 里算 → 数据存在千问的内置库 → AI 第一版不做 → 导出端点必做

这条路上没有任何一个组件在千问之外。它是唯一同时满足"可公开访问""完整功能""不碰任何红线"三条的路径。

一句话版：一个 .qwenwork.host 网址，页面 + 计算 + 存储 + 导出全在里面，对外只说"没有 AI"。
