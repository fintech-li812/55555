# 三层风控模型 v2：从 ST 判别转向现金流预警

修订日期：2026-10-22。审阅依据：用户提供的《三层风控模型公式与算法实现.md》及《三层模型验证结果.json》。

**结论：原方案存在标签含义、训练方向和验证口径问题，暂不足以支持真实现金流风险决策。v2 已提供公式修正和可运行参考实现；尚未完成真实企业数据的重训和效果验证。**

## 2. 新三层结构与核心公式

```text
原始流水/银行对账/应收应付/债务日历
  → 第一层：数据闸，失败=待复核
  → 第二层：未来13周现金与可用融资容量
  → 第三层：历史误差路径模拟 + 压力测试 + 可选路径下界校准
  → 规则灯色 + 具体原因 + 缺口金额 + 首次缺口周
```

### 第一层：硬质量检查，数字检验只做辅助

必须由数据接入端计算：银行对账是否一致、业务主键是否重复、应付税款工资等必要项目是否完整、数据是否足够新、币种单位及合并范围是否一致。任一必要检查失败，输出“待复核”，不补零、不出绿灯。

`risk_model.py` 消费这五项明确布尔检查；**它不连接银行，也不从一组布尔值证明数据已对账**。生产接入必须保存每项核查的明细和证据。技术缺失不改写为“企业经营高风险”。

Benford 只用于有合理产生机制、非人为编号、没有强制上下限等干扰的原始金额群体。不对 15 个混杂比率做整体拟合，不机械混合应收余额与现金收付；重复月末余额、固定价格、税率等需另外判断。正负金额可分组，零值单独记数。

适用且小样本时，按 Benford 概率生成 B 组多项计数，计算：

`p_MC = (1 + 模拟统计量≥观测统计量的次数)/(B+1)`。

多组筛查用 BH 调整 p 值；调整依赖其适用假设，强依赖检验可另选 BY/分组方案。p 值不是造假概率。末位特征必须基于原始分币与业务精度，不从已经缩放成万元或比率的数值反推伪造行为。

### 第二层：先回答“什么时候缺多少钱”

设 `C0=账面现金−受限现金`；R 为**现在可无条件动用、覆盖整个预测窗口的额外已承诺融资额度**，不是意向授信，不包含已提款且已计入 C0 的金额。到期、契约限制、费用与利息必须进入实际可用额度和付款计划；本参考实现只支持窗口内恒定 R，不支持复杂提款限制。

`C_t = C0 + Σ_{u=1..t}(I_u−O_u)`

`L_t = C_t + R`，表示现金加融资容量，**不是实际银行现金余额**。

`G = max(0, B_min − min_{t=0..13} L_t)`。

I 包含计划回款及其他确定来源；O 包含供应商、工资、税费、债务本金利息、资本开支等；不要把年报经营现金净流量按 13 等分代替付款计划。融资只加入一次。起始时点 t=0 同样检查；等于最低缓冲不算跌破。

本版按周末净额运算，可能漏掉周一付款、周五收款造成的周内缺口。工资、兑付等关键日期必须以日级计划复核；这是升级为生产模型前的必要项。

### 第三层：保留相关性的缺口情景

从**过去当时生成且现已到期的预测**计算成对误差：`e_t=(实际回款−原预测回款, 实际付款−原预测付款)`。这不是样本内拟合残差。

用循环移动块同时重采样两列，默认块长 4 周，保留局部自相关及收付款之间的相关性。不将两列独立抽样；不假设误差正态。每条路径：

`I_t^(s)=max(0, I_t+e_I,t^(s))`，`O_t^(s)=max(0, O_t+e_O,t^(s))`。

逐条累计得到 `G_s`，输出：

- 情景缺口比例 `Σ1(G_s>0)/S`；这是模型假设下的模拟频率，未经真实回测校准不能称真实缺口概率。
- `Gap_p95`：缺口分布的经验 95% 分位。
- `Gap_CVaR95`：按缺口从大到小排序，最差 ceil(0.05S) 条路径的均值；避免 VaR 为零时将所有零缺口也计入尾部。
- 平均与中位缺口、基准首个跌破缓冲的周数、压力缺口。

历史误差存在趋势漂移/业务变更时不保证块采样有效。至少 26 周只是程序最低门槛，不是统计充分性保证；真实使用宜覆盖完整季节周期并分业务验证。5,000 条路径增加的是模拟精度，不会把 26 周历史变成 5,000 个独立历史样本。截断负收付款也会改变分布，需做敏感性检验。

压力情景默认：回款减少 20%、回款延迟 2 周、付款增加 10%。只是待业务确认的假设，不是估计值。延迟后落在 13 周以外的回款会单列“窗口外回款”，不会伪装成永久损失。

可选路径下界校准：每个完整历史预测起点计算

`s_i=max(0,max_h(预测容量_i,h−实际容量_i,h))`。

取秩 `k=ceil((n+1)(1−α))` 对应的分数 q，未来路径下界为 `预测容量_h−q`。样本不足以取得该秩时拒绝输出有限下界。此分数针对**整条路径**，不能把各周 90% 区间当成 13 周联合 90% 区间。

普通分割共形的有限样本性质有可交换性条件，企业时序一般不能直接保证。代码只实现这一透明基线，不声称已经实现 SPCI 或 2025 在线优化算法；这些方法列为实测候选。

## 3. 第二层旧判别模型的数学修复

若仍需保留横截面财务健康度，先统一指标方向。以训练集确定 lo<hi：

`z_k=clip((x_k−lo_k)/(hi_k−lo_k),0,1)`；正向指标 `g_k=z_k`，逆向指标 `g_k=1−z_k`。

非正净资产下的 ROE、分母接近零的利息保障倍数不能当作普通健康度直接排序。应增加“非正权益”“零利息支出”“低分母”等状态特征，指标缺失/不适用明确处理；不可无条件填零。新缩放不能套用旧权重和旧阈值。

`score_i=w·g_i`，`w≥0, Σw=1`；令健康 `z_i=+1`、ST `z_i=−1`：

`z_i(score_i−c)≥m−ξ_i`，`ξ_i≥0,m>0`。

最小化按类别平均的松弛损失，避免大类别支配优化。代码函数 `fit_monotone_margin_lp` 实现上述训练；输出不是概率，也不是经典 DEA。正间隔避免同分数零损失，但不保证有信号，更不保证泛化。

保留 `D=2(score−c)` 的符号即可：D<0 为风险侧。上线只消费同一训练版本的全精度权重、缩放、列顺序、阈值。

## 4. 监督学习与验证怎么重建

已有 ST 面板只能重训“未来 ST 事件”目标；企业现金流目标建议定义为：预测日起未来 13 周内，在扣除受限资金、按契约认可融资后，是否出现无法覆盖必要付款的事件。事件定义、缓冲额、融资处理规则必须固定。

特征候选：应收账龄及逾期迁移、客户集中度、实际回款偏差、工资税费与债务到期、可用现金/刚性付款、经营现金流/到期债务、现金转换周期、滚动波动与趋势；盈利比率作为补充。预警标签不得直接由当期 ST 状态冒充未来事件。

`panel_train.py` 已提供独立的候选训练函数：

1. 输入每行公司、预测日期、所有特征最晚可得日期、标签窗口终点、目标标签及特征。
2. 按时间划分训练→校准/阈值选择→最终测试，清除标签窗口跨越下一阶段的行。数据披露日必须不晚于预测日。
3. 默认还要求三组公司完全不重叠，用于新公司泛化；若评估已有客户未来表现，可以显式关闭，但报告必须写清此范围。
4. 只在训练段拟合逻辑回归或浅随机森林；RF 固定 `n_jobs=1`。不做全面板先选特征，不用 OOB 替代时间外验证。
5. 独立后续时段拟合 sigmoid 校准，在同段按误报/漏报成本选择阈值，最终测试只评一次。该段既校准又选阈值，测试段仍须完全隔离。
6. 报告 ROC-AUC、Average Precision、Brier、混淆矩阵和真实样本比例。五个正例/负例仅为代码门槛；小样本指标不能当发布标准。

默认只称“样本特定校准分数”，不宣称总体概率。只有校准集代表目标总体、标签延迟与漂移等经检查，才能使用概率语义。50% ST 抽样不能直接推广。若仅先验改变且类条件分布稳定，可研究 odds 先验修正；本版未自动执行。

后续真实回测还需：滚动多折、公司级/时间块置信区间、行业分组、漏报提前量、固定告警工作量下的召回、Brier/可靠性曲线、与简单付款覆盖规则和季节朴素预测比较。路径模型需检查覆盖率、区间宽度和连续漏覆盖；相邻 13 周预测窗口高度重叠时不可按独立样本算置信区间。

训练函数是供开发者接入的 Python API，不是带数据接入及部署的完整训练平台；仅返回内存预测函数与报告。没有真实数据，交付不生成或替换生产权重。

## 5. 融合规则与表格落地

输出三字段：`quality_status`、`light/status`、`reason`。原因中可包含多个信号，但灯色只允许红灯、黄灯、绿灯或待复核，避免字符串后缀造成动作分支漏匹配。

新规则顺序：

1. 必要数据检查失败 → 待复核。
2. 基准融资容量跌破最低缓冲 → 红灯。
3. 模拟缺口比例≥暂定红阈值 0.30 → 红灯，明确是情景规则。
4. 模拟比例≥暂定黄阈值 0.10、压力路径跌破缓冲、可选路径下界不足，或未做真实验证 → 黄灯。
5. 在经批准验证范围内且以上条件均未触发 → 绿灯。

0.10/0.30 是演示配置，不是研究证明的最优值。`model_validated=true` 是调用方声明，不是程序自证；生产版本应由不可手改的验证审批记录与模型版本绑定。低 ST 分数不能冲销真实现金缺口，也不能排除舞弊。原 ST 模型与新现金流模型单列展示，防止同源财务特征被重复计权。

表格建议让 Python 回写 13 周路径、模拟结果、版本与时间；表格负责展示、引用与简单融合，避免在两个运行环境分别维护采样和模型训练。以下为支持英文函数名的表格模板，千问兼容性仍需实际工作簿验收：

```text
B2=账面现金；B3=受限现金；B4=已承诺可即用额外额度；B5=最低缓冲
C10:O10=13周计划回款；C11:O11=13周计划付款
B12=$B$2-$B$3
C12=B12+C10-C11            向右填充至O12（现金路径）
B13=B12+$B$4               向右填充至O13（融资容量路径）
B15=MAX(0,$B$5-MIN(B13:O13))
```

融合可用：`IF(质量状态<>"通过","待复核",IF(OR(基准缺口>0,模拟缺口比例>=红阈值),"红灯",IF(OR(模拟缺口比例>=黄阈值,压力缺口>0,路径下界缺口>0,验证状态<>"已验证"),"黄灯","绿灯")))`。这些名称为占位符，须绑定真实单元格/命名区域。

修复原动作漏匹配的最小改动是：灯色单元格只回写精确的“黄灯”，原因另列。程序只生成建议，不执行拉群、发消息、付款或授信操作。
